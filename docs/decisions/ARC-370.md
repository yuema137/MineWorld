## ARC-370 — Food energy is a kcal reserve variant of `needs`' one hunger state; invalid authored genesis is a domain-neutral kernel error; a new save is created only after a valid genesis

**Date** 2026-11-27 · **Status** accepted (design frozen; implemented by PR FE-a) · **Approved by** the operator, in the primary session, 2026-11-27: "同意三个都按推荐冻结" (step FE Q-FE-1 … Q-FE-5 as recommended) and "营养设计那两点、S34-c3 也全都同意你的推荐" (C-FE-2 confirmed: every existing save of a world that enables `needs` stops loading in the new build; Q-FE-6: per-person daily use deferred) · **Relates to** `CLAUDE.md` §4 rules 1, 2, 7, 10, 12; `INV-13`, `ARC-15`, `ARC-25`, `ARC-26`, `ARC-28`, `ARC-61`, `ARC-63`, `ARC-86`, `ARC-284`, `ARC-285`, `ARC-286`, `DEP-140` · **Design** `.structured-coding/plans/mvp0/step-fe-food-energy.md` §§1–4; `.structured-coding/plans/mvp0/pr-fe-a-food-energy-engine.md` §3 (contracts), §4 (consumer map); history in `.structured-coding/plans/mvp0/fe-evidence/`

**Problem.** The operator's playable-MVP requirement (`operator-playable-mvp-20261123.md` §§1, 2, 5) asks for food
energy in kcal: 2000 kcal per world day by default, configurable, refilled by realistically priced food bought
with money. `ARC-284` made hunger a unitless deficit in 0 … 1 000 with authored rates; nothing in it is a
calorie, and an item's `nourishment.hunger` is a unitless amount. At the same time three generic defects stood
in the way of refusing a contradictory food-energy world honestly: (1) a contradiction that can only be seen
once configuration and content meet (an initial reserve above the person's daily use) has no domain-neutral
error — `FactRefusedByOwner` is documented as a bug in a stating system, not authored input; (2) both CLI
new-save paths create `world.sqlite` *before* the pack assembles, so any authoring or genesis failure leaves an
empty save that the next launch tries to resume; (3) an Interaction List owner cannot declare its own schema
version or refuse a combination of fields that no single bound can express.

**Options considered.**

| Option | Verdict |
| --- | --- |
| (a) Relabel the deficit as kcal (1 000 points = one day) | Declined: a deficit is not a reserve, the 0 … 1 000 range cannot hold a configurable 2 000 or 2 400 kcal day, and authored `hunger_per_hour` rates would masquerade as physiology |
| (b) Replace the unitless model in every world | Declined: changes S35's behaviour and every needs world (Social Cafe, Market Town) without their authors choosing it |
| (c) A second hunger store (an `Energy` component beside `Needs`) | Declined: two ticking stores for one need, two writers of one fact's consequence, and a HUD/controller choice of which to believe (`CLAUDE.md` §4 rule 1) |
| (d) **A closed variant of the one hunger state: `Unitless(Level)` or `FoodEnergy { numerator, at }`, chosen per world by `hunger_model`** | **Chosen** |
| (e) Check the initial reserve against daily use with `mineworld_authoring::ResolvesSubjects` (contextual authoring) | Declined for this check: the effective daily use depends on the person's actor class resolved from the configured Interaction List, which is state reduced at genesis; a reduction-time check sees exactly what the person will have |

**Choice.**

- **Model.** `configure/needs.yaml` gains a base-only `hunger_model: unitless | food-energy` (default `unitless`,
  today's behaviour) and an actor-scoped `energy_kcal_per_day` (1 … 100 000), legal only in food-energy mode and
  required there as a base entry. In food-energy mode `hunger_per_hour` and `hunger_asleep_per_hour` are refused
  wherever written. Per-person daily use is not provided (Q-FE-6); a world varies it by actor class.
- **Arithmetic.** With `D` the effective daily use and capacity `C = D`, the reserve is stored as a numerator in
  kcal × 86 400 (`u64`) and the instant it was true; every product and time difference is computed in `i128`
  before clamping. `N(t) = max(0, N(at) − D·(t − at))`; eating `count` units of `K` kcal gives
  `min(C·86 400, N(t) + K·count·86 400)`. Readers see `available_kcal = ⌊N/86 400⌋`, an owner-computed bar
  `⌊1 000·N/(C·86 400)⌋` of 1 000, and a normalized hunger `⌊1 000·(C·86 400 − N)/(C·86 400)⌋`, whose words use
  the existing thresholds, *at or above*. A food's motivation score for controllers is
  `⌈1 000·min(K, C)/C⌉` (0 for `K = 0`); it ranks food and never changes the reserve. A zero-kcal consumption
  writes nothing. No Process, no runtime fact, no random draw; world time only (`ARC-86`).
- **Reference values.** The 2 000 kcal default is the FDA Daily Value reference intake on US Nutrition Facts
  labels (21 CFR 101.9(c)(9)): the operator's game default, not personal advice. The drain is the same asleep and
  awake, a deliberate simplification (operator-playable-mvp §5: "fixes the example default, not a physiological
  model"); real sleeping expenditure is near basal rate, roughly 60–70 kcal/h for a typical adult against the
  83 kcal/h daily average, so night drain is modestly overstated. Unitless worlds keep S35's slower hunger in
  sleep. An optional asleep fraction is a deferred extension.
- **Serving.** A food-energy item states `energy_kcal` (0 … 100 000) for one whole serving and a `serving
  { label, quantity { unit: g | ml, amount } }`. One inventory unit is one whole serving: no fractions,
  unpacking or recipes.
- **Disclosure.** The holder-only `needs` record (schema 2) names `hunger_model`; in food-energy mode it adds
  `food_energy { unit: "kcal", available_kcal, capacity_kcal, use_kcal_per_world_day, bar { value, maximum },
  replaces_need }`, where `replaces_need` names the need the reserve stands for so a generic reader swaps the row
  without naming it. Clients, agents and prompts compute no kcal, rate or threshold.
- **Versions.** `NeedsSystem` 2; `Needs`, `Nourishment`, the `needs` record, `needs-assigned`,
  `nourishment-assigned`, `needs-interactions-configured` and `needs-interactions` 2. Every other pack is
  unchanged. Old saves of a needs-enabled world are refused with the first applicable explicit error (the
  configuration drift on `needs-interactions-configured`, else `PersistedSystemOutdated`), their committed
  contents logically untouched; no migration, reset or re-genesis (C-FE-2). Keeping unitless at schema 1 was
  rejected: a persisted version is per System and per component/event type, not per variant.
- **SDK seam.** `InteractionSection` gains `CONFIGURED_SCHEMA_VERSION` and `COMPONENT_SCHEMA_VERSION` (both
  default 1) and `validate_authored(section, resolved)` (default no-op), called once inside `resolve`, so the
  load check and the genesis seed cannot disagree. `ConfigurationRefusal::Owner { entry, code, detail }` carries
  an owner's refusal with the entry it names; the loader reports it with the file.
- **Kernel error.** `KernelError::InvalidGenesisContent { system, subject: EntityKey, code: RejectionCode,
  field, detail }`: an owner reducing a fact caused by `WorldGenesis` found authored content contradictory.
  Construction stops and the candidate world is discarded. `field` and `detail` are bounded human text, never
  matched by code; the typed identity is `system`, `subject` and `code`. It knows nothing of food, money or
  needs. A non-genesis contradiction keeps `FactRefusedByOwner`; dispatch enforces nothing and treats this error,
  if ever returned outside genesis, like any other reduction fault. This amends S35's I-S35-1 ("the kernel and
  contracts are unchanged") by this one error; the contracts crate is unchanged.
- **Valid-genesis-first saves.** `PersistentWorld::create_with_backend(world, creation, make_backend)` makes the
  backend only after the snapshot, the one in-memory genesis and every encoding have succeeded. `create(backend,
  …)` remains for callers that already own a scratch or in-memory backend (not a compatibility adapter). Both CLI
  new-save paths assemble first and pass the factory, so an invalid world leaves no save and binds no port.

**Consequences.** A world chooses food energy by data alone; a second world with another currency and 2 400 kcal
works without kernel or client edits. `economy` still alone owns money, `inventory` holdings, `consumption`
stays stateless. Market Town content (prices, servings, wallets, USD 10 000 for the visitor) is FE-b's.
Every save of a needs-enabled world made by an earlier build needs that build (CHANGELOG).

**Revisit** when per-person daily use, an asleep fraction, hydration or a consequence of an empty reserve is
asked for, or when a second owner needs `InvalidGenesisContent`.

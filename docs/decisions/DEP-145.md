## DEP-145 — Rejected for clipping checks, with reasons: Open3D, Coal, CGAL, ContourCraft and HOOD; IPC Toolkit deferred

**Date** 2026-10-19 · **Status** accepted (step 36 frozen 2026-10-19) · **Approved by** operator, primary session, 2026-10-19 (step 36 freeze) · **Relates to** `DEP-142`, `DEP-143`, `DEP-144`, [`REUSE_POLICY.md`](../REUSE_POLICY.md) · **Design** `.structured-coding/plans/mvp1/step-36-interpenetration.md`; facts read at their package indexes and repositories on 2026-10-19 (`mineworld-demos/research/clipping-tools.md`, sources listed there)

**Problem.** `CLAUDE.md` §4 rule 16 asks both halves of the reuse question. The candidates below were read at their
source and each fails on platform, licence or fit. The record keeps a later session from re-opening them without new
facts.

**Rejected, with the deciding fact.**

| Candidate | Deciding fact | Verdict |
| --- | --- | --- |
| **Open3D** `RaycastingScene` (MIT, 0.20.0) | Its signed distance is "only valid for watertight meshes" (its own tutorial); Meshy bodies and garment shells are open. macOS wheel for arm64 only; Linux needs glibc ≥ 2.35. A large dependency for what libigl does better | Rejected |
| **Coal** (formerly hpp-fcl; BSD, 3.0.3) | No Windows wheel on PyPI (conda-forge only); our CI and tooling are pip/uv on all three platforms | Rejected; revisit if a PyPI Windows wheel appears |
| **CGAL** Polygon Mesh Processing (`cgal` Python wheel) | GPLv3+ (commercial otherwise); no macOS arm64 wheel seen; last wheel 2024-10 | Rejected (licence, platform) |
| **ContourCraft** (SIGGRAPH 2024) and **HOOD** (MIT code) | CUDA 12.4 + PyTorch + RAPIDS, Linux-only install, and they need the SMPL body model, whose licence is separate and non-commercial; our bodies are not SMPL | Rejected |
| DIG, vto-garment-collisions | No licence or NOASSERTION; SMPL-bound research code | Rejected |
| NVIDIA Kaolin (`check_sign`) | CUDA PyTorch; not runnable in our CI | Rejected for CI |
| `SkeletonIK3D`, GodotIK, Many Bone IK | Deprecated or superseded by Godot's built-in IK (`DEP-144`) | Rejected |
| IfcOpenShell `ifcclash` (LGPL-3.0) | IFC/BIM data model; not ours | Rejected |

**Deferred, not rejected.** **IPC Toolkit** (`ipctk`, MIT, 1.6.0) is the only option that checks *between* two
sampled poses (continuous collision detection), which catches a fast limb tunnelling through the trunk between two
frames. It has no macOS x86_64 or Linux aarch64 wheel, and sampling every frame at the clip's 30 fps is enough for
the gaits we have. Revisit if a tunnelling clip is seen. **manifold3d** (Apache-2.0) needs manifold inputs; it is used
only indirectly, as trimesh's boolean engine.

**Choice.** None of the above is adopted. The adopted set is libigl (`DEP-142`), trimesh + python-fcl (`DEP-143`) and
Godot's built-in IK (`DEP-144`).

**Consequences.** Nothing is installed for these. A pack author may still use any of them in their own tooling under
its own licence.

**Revisit** when a rejected candidate's licence or platform support changes.

## ARC-146 — A world's 3D presentation file is `3d-<world-key>.pck`; a world without one is refused by name

**Date** 2026-10-19 · **Status** accepted (PR S33-c design frozen 2026-10-18); this record's first half implemented by S33-c, the export by S33-j · **Approved by** the operator's ruling Q-S33-3 (PK-2) and the freeze of `pr-s33c-world-seam.md` (2026-10-18) · **Relates to** `ARC-102`, `ARC-144`, [`MODULE_SPEC.md`](../MODULE_SPEC.md) §6 · **Design** `.structured-coding/plans/mvp0/pr-s33c-world-seam.md` §§5.3, 5.8; `step-33-lakeside-3d.md` §§8.2, 16.4

**Problem.** One Presentation Pack can present several worlds, and a world's 3D depiction can be large (Lakeside's village, S33-d…g). Shipping every world's depiction inside the one client export makes every download carry every world, and gives no way for the client to say that it lacks a world's presentation: before this record, a key the client could not draw silently drew the café street.

**Options considered.**

| Option | Verdict |
| --- | --- |
| (a) Every depiction in the one export, no refusal | Declined: a missing depiction is drawn as another world |
| (b) A fallback depiction (flat ground, generic boxes) for any key | Declined (Q-S33-3): a fallback looks like the world and is not it |
| (c) **One export file per world, loaded at start with Godot's `ProjectSettings.load_resource_pack`; a key whose depiction is still absent is refused by name** | **Chosen** |

**Choice.** One Presentation Pack may ship per-world 3D export files named `3d-<world-key>.pck`, beside the client executable. At start the 3D client looks for the key's depiction; when it is absent it loads `3d-<world-key>.pck` if that file exists, then looks again. When the depiction is still absent, the client refuses `PRESENTATION_WORLD_MISSING { world: <key> }`: the line `[mineworld-slice] PRESENTATION_WORLD_MISSING: { world: <key> }: this client has no depiction for the world; install its 3D presentation file 3d-<key>.pck` is printed and shown full-screen, and a scripted run exits 3. The depiction is checked before the far field, so a missing depiction is named as such. A client joining a server with no `--world-key` is refused `FAR_FIELD_WORLD_UNKNOWN` by the far-field loader, unchanged. There is no fallback depiction.

**Consequences.** S33-j splits the export: `scripts/depictions/lakeside/` and its assets go into `3d-lakeside.pck` and leave the main export; the registry needs no change (R-S33j-c-1). In the editor and the development tree every depiction is present, so nothing is loaded.

**Limitation accepted.** Until S33-j, no `.pck` is produced, so the loading branch runs only when someone places such a file by hand.

**Revisit** when S33-j lands the export, or when 16f moves depictions into Presentation Pack data.

**Note (2026-10-20, S14 16f-b; the operator's Q-16f-1 (A) at the freeze of `pr-16f-presentation-pack-3d.md`).** The refusal is narrowed by `ARC-52` point 5. A world key with no depiction script and no `3d-<key>.pck` is no longer refused: it is drawn plainly from the server's disclosure (`SlicePlainDepiction`; the far field from the pack, plain ground, every place from its own `place-shape`, the HUD note `hud.depiction.plain`). Every wall drawn is the server's own, so this is not the fallback option (b) declined. A pack without that world's far field is refused `FAR_FIELD_MISSING` by the far-field loader, before anything is drawn. `PRESENTATION_WORLD_MISSING` remains for a key that is not a world key (empty, or a path); the `.pck` lookup is unchanged.

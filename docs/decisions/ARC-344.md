## ARC-344 — The 2D link resumes with the module's `resume`, ends on the seat codes, and takes a seat over only when the player asks

**Date** 2026-10-20 · **Status** accepted · **Approved by** the operator's freeze of PR 13e (2026-10-20, Q-13e-1, Q-13e-2, Q-13e-8) · **Relates to** `ARC-47`, `server/PROTOCOL.md` §§4.2, 5.5–5.8 · **Design** `.structured-coding/plans/mvp0/pr-13e-many-players-2d.md` §§5.1, 5.2, 5.5 (SD-13e-1, SD-13e-2, SD-13e-5)

**Problem.** Since S11-B a seat is exclusive and a dropped connection's seat is held for 30 s for its `resume`. The 2D link re-joined with plain joins: during the hold its own seat answered `seat_occupied`, and the link stopped. A player whose seat was taken (`closing taken_over`) was retried for ever, because `taken_over`, `superseded` and `kicked` were not final.

**Choice.**

1. `clients/2d/scripts/link.gd` turns the module's opt-in `reconnect` on, so a drop resumes the same seat with `resume` inside the hold. If the module gives up, the link's own capped back-off continues with plain joins (a restarted server holds no seat).
2. The codes the link ends on are `unauthorized`, `unknown_seat`, `seat_not_in_world`, `invalid_nickname`, `protocol_mismatch`, `already_joined`, `not_granted`, `seat_occupied`, `left`, `taken_over`, `superseded`, `kicked`. The link then emits `ended(code)` and the client shows the join screen with that answer.
3. A takeover is never automatic. After `seat_occupied` the join screen offers **Take over**, which sends the same join with `take_over: true`. A later automatic rejoin never carries `take_over`.
4. The join screen appears when no `--seat` is given and after any final answer. It lists `GET /status`'s `seats` as they are; `/status` names no player, so the screen does not say which seats are free. The server's answer says so.
5. The shared module (M-8): with `reconnect` on, `closing { reason: "lagged" }` resumes like a drop, as `PROTOCOL.md` §5.8 already says a lagged client does. Off by default, so no other caller changes.

**Consequences.** A blink comes back as the same Person without anybody noticing (`took_over "held"`). Two players asking for one Person get a clear refusal and a deliberate choice. No rule is in the client: every decision is a server code the client reacts to.

**Revisit** when `/status` or an admin-free surface says which seats are free, or when the 3D client adopts the join screen (move it to `clients/shared/`).

## DEP-142 — Mesh inside/outside and depth: libigl (MPL-2.0 core only), behind `mwcast/contact.py`

**Date** 2026-10-19 · **Status** accepted (step 36 frozen 2026-10-19; adopted in PR S36-P1) · **Approved by** operator, primary session, 2026-10-19 (step 36 freeze, Q-S36-5) · **Relates to** `DEP-13`, `DEP-143`, `DEP-145`, [`REUSE_POLICY.md`](../REUSE_POLICY.md) · **Design** `.structured-coding/plans/mvp1/step-36-interpenetration.md` §3; `pr-s36-p1-contact-module.md`

**Problem.** The operator ruled (2026-10-19) that every person, garment and item is checked for ground contact and
interpenetration. The checks today are hand-written geometry: 2 cm slabs, a 48-direction outline, ray parity. They
misread layered garments (F-S32p-6) and open shells. A Meshy body or a garment is often open at the neck and the cuffs,
so a ray from an inside point can leave through the hole and read "outside".

**Choice.** Adopt **libigl** through its Python bindings (`libigl` on PyPI, 2.6.3, 2026-09-01), pinned in the root
dev dependency group and in `tools/character_pipeline/requirements.txt`. Use only functions of its MPL-2.0 core:
`fast_winding_number`, `winding_number`, `signed_distance`, `point_mesh_squared_distance`, `AABB`. The generalized
winding number (Jacobson et al. 2013) is about 1 inside and 0 outside even on open or self-intersecting meshes, so a
0.5 threshold answers "inside?" robustly; the distance gives the depth.

**Why this and not another.** It is the only candidate that answers "which vertices of A are inside B, and how deep"
on non-watertight meshes. Wheels exist for macOS (x86_64, arm64), manylinux (x86_64, aarch64) and Windows (amd64), with
an abi3 wheel for 3.12+. Open3D's sign is valid only for watertight meshes; CGAL is GPL (`DEP-145`).

**Licence boundary.** The package also ships `igl.copyleft`, which wraps GPL code (CGAL). It is never imported. A test
in `tools/character_pipeline/tests/test_contact_licence.py` fails if any file imports it or if it appears in
`sys.modules` after the contact module runs (invariant I-S36-1).

**Consequences.** The pipeline stops being stdlib only: numpy and libigl are installed by CI's Python environment and
the operator's tooling venv. They are never a runtime dependency of the server, a client or a pack. Only
`mwcast/contact.py` imports `igl`.

**Revisit** if the bindings stop shipping a wheel for a supported platform or Python, or if the MPL core changes licence.

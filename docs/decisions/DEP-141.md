## DEP-141 — Git LFS stores the cast's generated characters; a checkout without LFS degrades to the town figure

**Date** 2026-10-19 · **Status** accepted; in use since `b805ddaf` (S26-c1) · **Approved by** the operator, 2026-10-19 ("commit via Git LFS now, compress the release later"), relayed by the coordinator session · **Relates to** `ARC-9`, `ARC-92`, `ARC-93`, `DEP-45`, [`REUSE_POLICY.md`](../REUSE_POLICY.md) §§11–12 · **Design** `.structured-coding/plans/mvp0/pr-s26c1-cast-client.md` §3 D-3, `.structured-coding/plans/mvp0/step-26-cast.md` §10.3

**Problem.** Every cast character is a glTF with a ~4 MB vertex buffer and a ~6 MB base-colour texture (`clients/3d-spike/assets/characters/cast/<id>/`). Ten are committed now and the step plans about twenty more. Committed as ordinary blobs they grow every clone's history by about 10 MB per Person, and a re-generated character adds another 10 MB that never leaves the history.

**Options considered.**

| Candidate | Verdict |
| --- | --- |
| Plain Git blobs | Declined: history grows by every version of every character, for every clone, forever |
| **Git LFS** (`git-lfs`, MIT; GitHub-hosted storage) | **Adopted** for `clients/3d-spike/assets/characters/cast/**/*.bin` and `**/*.png` only. The `.gltf` (JSON, ~22 kB) and every `.import` stay plain text, so diffs, reviews and the importer's settings stay readable |
| A release-asset download (fetch at build time) | Declined for now: it is a second distribution channel to maintain before the release packing exists (S26-f decides the release's own compression, step-26 §10.3) |
| Compress first (meshopt, KTX2), then commit plainly | Deferred, not declined: the operator ruled the compression into the release step; it reduces the size, it does not stop history growth |

**Choice.** Git LFS, with the `.gitattributes` lines committed in `b805ddaf`. **No CI job fetches LFS objects**: CI checks out pointer files. The 3D client therefore never assumes a character's files are real: `SliceCast.body_for` (`clients/3d-spike/scripts/slice/cast_binding.gd`) reads the first bytes of the scene, its `.bin` and its `_base_color.png`, and a file beginning `version https://git-lfs` makes that Person the town figure with one warning naming the file. Godot's `--import` of a pointer glTF prints importer errors and exits 0 (measured, Godot 4.7.2: `ERROR: glTF: Couldn't load image …`, `Condition "inv_binds_arr.size() != joints.size()"`, exit 0), so the CI import step and `tools/cli/tests/client_far_field.rs` `import` (which judge the exit status) are unaffected, and the client never loads the failed import.

**Consequences.** A developer needs `git lfs install` once to see the characters; without it the town is drawn with the town figure and says why. The 2D sprites rendered from these characters are small (~110 px) and stay plain Git. The release packing (S26-f) must run with LFS objects present, and checks that a packed character is not a pointer. GitHub's LFS bandwidth and storage quotas now apply to the repository.

**Revisit** when the release compression lands (S26-f), if LFS quotas bind, or if CI gains a job that must render the characters themselves (it would then need `lfs: true` on its checkout).

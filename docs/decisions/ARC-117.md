## ARC-117 — Pricing policies are decision-model parameters and models, defaulting to `hold`

**Date** 2026-10-26 · **Status** accepted · **Approved by** the operator, 2026-10-20, primary session (S31-d's design frozen with every question ruled as recommended; step-31 Q-S31-5) · **Relates to** `ARC-34`, `ARC-35`, `ARC-112`, `ARC-113`, `ARC-115`, `ARC-116`, `ARC-182`, `ARC-27` · **Design** `.structured-coding/plans/mvp0/pr-s31d-reporter-policies.md` §§5.4 … 5.6

**Problem.** Any seller sets its own price (`ARC-112`), and a world may publish suggested prices on a notice topic (`ARC-115`, `ARC-116`). Step-31 §0.1 item 6: "Pricing models may read suggestions, so that prices converge." Something has to turn a suggestion, or a seller's own stock, into a `set-price` — and a world must be able to choose whether and how, by configuration, with every existing world deciding exactly as before.

**Options considered.** (a) A third decision model per seller kind — rejected: a keeper would lose `rule`'s or `motivated`'s daily life, or every policy would be a model per daily-life model. (b) A world rule in economy that moves asks toward the market — rejected: it would read trades nobody perceived, and the seller's price would no longer be the seller's choice. (c) **A shared, typed `pricing:` block in `rule` and `motivated`, default `hold`** — chosen (Q-S31-5).

**Choice.**

1. **The block.** `pricing: { sell: { policy, every_minutes, step_permille, deadband_permille, floor_permille, ceiling_permille, low_below, full_above, list: { categories }, tags }, buy: { choose, tags } }`, decoded by hand, every key optional, unknown keys and out-of-range values refused at their key. `sell.policy` is `hold` (default), `toward-suggestion` or `scarcity`; `buy.choose` is `any` (default: today's draw) or `cheapest`. A custom algorithm is a model in `models!`, not a new policy name.
2. **Halves with tag filters.** A decision list configures each model once, not each seat (`ARC-84`), so each half carries `tags:`: a seat applies the half only when its own disclosed tags include one of them (empty: every seat on the model).
3. **What a seller prices.** Its own `asks` view; and a shop's listing when it keeps the shop it stands in — inferred from `set-price` being offered while it has no asks of its own. One request per consult: within each `sell.every_minutes` period, index 0 lists a held kind of a listed category at its reference value (`list-for-sale`), and index `j ≥ 1` prices the `j − 1`th priceable ask. The index is `floor((t mod period) / pace)`, so each slot is handled exactly once with no memory.
4. **The source of suggestions** is only the observer's own `notice-board` record, which lists current notices only: an expired suggestion is never used (I-S31-8). Among lines for one item, the newest `issued_at` wins; ties go to the lower publisher id, then the lower topic.
5. **Bounds.** Every proposed price lies in `[max(1, reference × floor ÷ 1 000), max(that, reference × ceiling ÷ 1 000)]` and ≤ 10^12; a kind with no reference value (`ARC-113`) is never moved or listed; a price equal to the current one is not sent. `toward-suggestion` moves `step_permille` of the gap (at least one minor unit) unless the gap is within `deadband_permille` of the ask; `scarcity` moves by `step_permille` of the ask when stock is below `low_below` or above `full_above`.
6. **The buyer hook.** When `buy.choose` is `cheapest`, a `buy` the model already chose is replaced by the cheapest available complete `buy` of the same item (the first in observation order on a tie). It takes no draw.
7. **Reading the market.** The policies live in `mineworld_rule_controller::price` and read the market packs' records and build their requests by slug, through wire mirrors (`ARC-182`).

**Consequences.**

- **Default parity.** With no `pricing:` block, `rule` and `motivated` submit exactly what they submitted before, and no policy takes a draw.
- **Keeper limit.** A keeper who also sells on its own account prices only its own asks (economy discloses no `keepers`); a later disclosure lifts it.
- **WE-a modifiers.** A shop listing shows the price after a happening's adjustment and does not disclose the adjustment, so while one runs a policy may propose a move from the adjusted price; economy refuses or applies it to the base ask. Recorded until economy discloses adjustments.
- **S31-h** (haggling) attaches `sell.accept_at_least_permille` and `buy.haggle` to these halves and its two functions to `price/haggle.rs`; until then the decoder refuses those keys.

**Revisit** when per-seat parameters exist in decision lists, or a seller needs a policy the block cannot express.

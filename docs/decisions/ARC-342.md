## ARC-342 — The 2D client draws loose objects, plays their paths with Godot's Tween, and aims a throw on the offer

**Date** 2026-10-20 · **Status** accepted (design frozen by the operator, 2026-10-20; implemented in
S12 PR 13d) · **Relates to** `ARC-47` (no rule in the client), `ARC-34` (complete affordances),
`ARC-307` (furnishings drawn), `ARC-75` (server routing), step-11 §22 SD-E6, SD-E7, SD-E11, QB-7,
`.structured-coding/plans/mvp0/pr-13d-bodies-2d.md`, `step-13-client-2d.md` §5.4 (one row superseded)

**Problem.** The `bodies` System Pack discloses each place's loose objects (`loose-objects`:
`[{object, shape, at, tags?}]`), states every move as an `object-moved` fact with a `path` of keyframes,
and offers complete `kick { object }` and `throw { object, toward: null }`. The 3D client drew and
moved them (S15 12e); the 2D client drew none, so a 2D player could kick a ball they could not see, and
had no way to ask for an aimed throw.

**Choice.**

1. **Drawn = disclosed.** `clients/2d/scripts/scene/objects.gd` draws every entry of the observer's
   place's listing at its `at`, by its disclosed shape: a ball as a disc of its radius, a box as its
   footprint, an unreadable shape as a 0.2 m outline square (never skipped). A Presentation Pack may bind
   the role `object.<shape>`; unbound, plain drawing is complete. Nothing names an object, a place or a
   world.
2. **Motion is the owner's.** When the observation that moved an object carries its `object-moved`
   fact with a non-empty `path`, the drawing plays the keyframes in order, 0.1 wall s each, and ends
   exactly on `to`; otherwise it eases to the new `at` (distance / 4 m/s, between the walker's glide and
   0.8 s). A newer move kills the running one and starts from the drawn point. The drawing never moves
   except toward a position an observation states (QB-7); the world's time scale is never read (SD-E11).
3. **The object menu is presentation.** A click on a drawn object (after people, who are picked first)
   opens a menu of the player's target-less offers whose payload refers to it, in the server's order;
   with none, the click walks to where it lies (`walk-to`, the server routes). The player's own menu
   still lists every offer.
4. **The aimed throw is the offer, aimed.** After an offered complete affordance whose type
   `intents.gd` aims (`INPUTS["throw"] = {aim: true}`; `throw` joins `COMPOSED`), the object menu lists
   "Throw <object> at…". The next floor click sends that offer with `toward` set to the clicked point,
   integer millimetres of the place's frame; the object reference is the offer's, unchanged, so the
   client never builds an identity. Esc, a right click, a place change or the object leaving the listing
   drops the aim and sends nothing. The point is never checked: the server throws, clamps or refuses
   (`ARC-47` R3). The one event type the client reads, `object-moved`, is named in `intents.gd` beside
   the action types.

**Alternatives for the motion (tools first).**

| Option | Verdict |
| --- | --- |
| Godot `Tween` (one `tween_property` per keyframe, physics process mode; MIT, every platform) | **Adopted**: plays the server's points as given, ends on the last, kills cleanly |
| `Path2D` + `PathFollow2D` + `Curve2D` | Rejected: bakes and smooths the curve, so the drawn path is not the server's points |
| `AnimationPlayer` with a generated `Animation` | Rejected: heavy for a one-shot per fact |
| A hand lerp in `_physics_process` (what the 3D client does) | Rejected for 2D: `Tween` does it with no code of ours; 3D keeps its own |

**Supersedes** the step-13 §5.4 row "Adopt NavigationServer2D … (PR 13d)", already withdrawn by operator
ruling QN-8: the server routes every walk (`ARC-75`), and the client plans none.

**Why.** Every rule stays the server's: whether an object can be kicked or thrown is an offer, where it
lands is a fact, and the 2D client only draws and asks. The same listing, facts and offers drive both
reference clients, so one world reads the same in 2D and 3D, and a world with other objects, places or
shapes needs no change to the client.

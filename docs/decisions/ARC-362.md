## ARC-362 — The onboarding cold-start check: a clean runner, the guide in cold-start mode, the bundle check

**Date** 2026-10-27 · **Status** accepted (operator ruling of 2026-10-27, every question Q-25g-1 … Q-25g-10
answered as recommended; implemented in PR 25g) · **Relates to** `ARC-48` (CI layers; check names are an
interface), `ARC-83` (the nightly), `ARC-154` (speed first), `ARC-90` and `DEP-50` (the executable guide),
`DEP-19` (pinned runner labels), step-25 INV-S25-3 and INV-S25-6 · **Design**
`.structured-coding/plans/mvp0/pr-25g-cold-start.md`

**Problem.** The guide test runs every guide page on Linux, macOS and Windows, but on a machine that already has
Rust, Git LFS and a warm build. Its `git clone` reads the local checkout, and every `mineworld` command runs the
test's own binary. So nothing showed that a stranger with a clean computer can follow the guide from its first
line, or that the downloadable bundle runs the guide with no Rust and no Godot.

**Choice.**

1. **A new workflow, `.github/workflows/cold-start.yml`, never a required check.** Triggers: a weekly schedule,
   `workflow_dispatch`, `workflow_run` on the release workflow ("Release") for layer B, and pushes to
   `cold-start/**` for pre-merge evidence. Never `pull_request`. Jobs `cold-start-harness (<os>)`,
   `cold-start-a (<os>)`, `cold-start-b (<target>)` and the summary `cold-start`. A red run is reported in the job
   summary only (Q-25g-9).
2. **Layer A, from source.** A fresh hosted runner per OS (`ubuntu-24.04`, `macos-26`, `windows-2025`) removes the
   preinstalled Rust and Git LFS and proves them absent by behaviour (each command not found). The guide runner in
   cold-start mode (`docs/GUIDE_FORMAT.md` §4.7) then follows the pages: chapter 01's own install commands, a real
   clone from GitHub with `git lfs pull`, the reader's build, and every page with the reader's
   `target/release/mineworld`. Each page's time is recorded. Pass bar: zero to Corner Shop (start of the clean
   step to the end of chapter 05) within 60 minutes of machine time per OS (Q-25g-7).
3. **Layer B, from the download.** The bundle a successful release-workflow run uploaded (`MineWorld-<target>`, one
   archive) is unpacked as a player would, on a runner with no Rust and no Godot (asserted), and chapters 02–06 run
   with the bundled `runtime/mineworld`.
4. **One runner, two modes (option C3).** The guide test executable is built once per OS in a helper job (which may
   restore the existing Cargo cache, Q-25g-8) and copied, as one file, to the clean runner, which never compiles
   test code. Declined: C1, a second parser of the guide in Python (two parsers drift); C2, building the test on the
   clean runner after chapter 01 (the runner must exist before Rust does, and a test build could shadow the reader's
   binary); C4, containers (no macOS or Windows containers on hosted runners).
5. **Chapter 01 gains the install commands (option P1, Q-25g-1, Q-25g-2).** Per-OS `sh` and `powershell` blocks for
   Git LFS and Rust, and `git lfs pull`, marked with the new directive `<!-- guide: cold-start -->`: run in
   cold-start mode, listed as not run in the default test. Declined: P2, a CI script installing the tools, which
   tests a script rather than the guide and leaves a reader without a command. Chapter 01 names the C compiler a
   build needs (Q-25g-3).
6. **Operator-only blocks get substitutes, never a model (INV-S25-6).** 06.2 and 14.2/14.10: the server started
   headless with the page's own command line and matched against the page's lines. 06.3 on Linux and macOS: the 2D
   client's `--drive=walk` against that server with CI's pinned Godot, installed only after chapters 01–05 ran
   (Q-25g-4). 14.3–14.7: the page's own `uv sync` block, then the recorded agent session replayed through the real
   MCP adapter (Q-25g-5). Not covered: 06.3 on Windows, 14.8, 14.9, any live model. Each substitute is reported
   under its own name.
7. **Before a tag:** a manual dispatch in the release checklist. After three consecutive green weekly runs, R-b's
   `verify-tag` may require a green run on the tagged commit (Q-25g-6); the summary job's name `cold-start` then
   becomes an `ARC-48` interface, recorded then.

**Not achievable, and not claimed.** The C toolchain stays on every runner (Visual Studio with C++, Xcode Command
Line Tools, gcc/clang); so do Git, Python, Homebrew and PowerShell. The network is GitHub's. Times are machine
times, not a reader's. The image is not a fresh OS. Every run's summary says so.

**Cost.** No money: hosted runners are free on this public repository and no model is called. About 0.63 GiB of
Git LFS bandwidth per layer-A run (three clones) against the 10 GiB monthly quota. macOS runner slots (cap 5): at
most two jobs of this workflow at a time.

**Consequences.** `docs/GUIDE_FORMAT.md` gains §4.7 and the `cold-start` directive. `release.yml`'s workflow name and
its artifacts `MineWorld-<target>` are an interface this workflow reads (pr-s23-rb §4.3). The default guide test is
unchanged except the `cold-start` entries of `expected_run.toml` and one timings line.

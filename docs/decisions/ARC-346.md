## ARC-346 — Demo A's acceptance run is one story on two worlds, played by the real 2D client from disclosure

**Date** 2026-10-20 · **Status** accepted (design frozen by the operator, 2026-10-20; implemented in
S12 PR 13f) · **Relates to** `ARC-23` (bounds decided before measuring), `ARC-47` (no rule in the
client), `ARC-174` (the parity test's file), `ARC-342` (2D loose objects), `docs/MVP.md` §7.1,
`.structured-coding/plans/mvp0/pr-13f-demo-a-proof.md`, `pr-16e-demo-b-proof.md` (Q-PAR-1)

**Problem.** Every item of `MVP.md` §7.1 (several people and places, movement, conversation,
relationships, items, a group activity, persistence, human and agent controllers, several players)
was proven by a separate test, and only on market-town. Nobody played them as one story, and nobody
played them on a second world, so a mechanism that only works for the default town would pass.

**Choice.**

1. **One story.** The Demo A acceptance run is `tools/cli/tests/demo_a.rs` (`#[ignore]`, needs Godot):
   the §7.1 list played in order by the real 2D client against a hosted world (`--town`, `--save`),
   with two clients, hosted agents, a `SIGKILL` of a client and of the server, and resume. It is the
   S12 checkpoint.
2. **Two worlds, chosen from disclosure.** The same code plays market-town and social-cafe. No step
   names a world's person, place or item: "talk to someone" picks the first person the observation
   offers `talk` against; "use an item" picks the first complete offer of the observer's own menu
   about an item or loose object (a `buy` in market-town, a `kick` in social-cafe).
3. **Oracles outside the client.** Every assertion reads the save's fact log, `GET /status` or another
   connection; the client's own `[PASS]` is never enough.
4. **The 2D report says what is drawn.** `SHOWN` lists doorways read from the drawn scene (not the
   layout model), the loose objects drawn, and each menu's offers; `IDENTITY_WORLD` names the instance,
   the revision, the people by id and disclosed name, and the `EventId`s seen. The presentation-only
   keys are declared once in `clients/protocol/ADOPTION.md` §7. A harness-only `--drop-doorway` makes
   the parity test's negative case a standing run. The parity test itself is S14 PR 16e's
   (`shown_parity.rs`, Q-PAR-1).
5. **Persistence across a server restart** is three facts (Q13f-3): the facts before the kill are a
   prefix of the facts after; the restarted welcome names the same instance; its revision is at least
   the save's last revision read between kill and restart. Hosted agents keep the clock moving, so
   "the same revision" would be false for a correct world.

**Rejected.** Editing the existing `client_2d*.rs` tests into one (they stay focused regression tests);
a Godot-side story scenario (the Rust test owns the oracles); hosting the parity test here (it needs
the 3D client, and 16e already waits on S12).

**Consequence.** A third world joins Demo A by adding one world path to `demo_a.rs`; a world with no
complete item offer in reach fails step 7 by name as a content gap, never skipped.

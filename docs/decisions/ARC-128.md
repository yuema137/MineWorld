## ARC-128 — Runtime sampling for predeclared people admitted later

**Date** 2026-10-27 · **Status** accepted design, implementation in S30-j · **Approved by**
operator freeze of pr-s30j-runtime-sampling.md, all three recommendations accepted in the
primary session · **Relates to** ARC-120, ARC-121, ARC-123, ARC-25, ARC-26, QPL-11.

**Problem.** A person joining a running world needs profile values drawn against the
population present at that instant, with authored and locked values preserved and the
result reproduced by persistence replay. A System receives WorldView, which cannot create
an entity. Runtime entity creation is a separate kernel design (QPL-11).

**Options.** (a) Predeclare people, defer their attributes and admit them in a dispatch;
(b) first extend the kernel's entity-creation contract. Choose (a). This does not grant
Systems runtime entity creation, change the entity registry or add a kernel vocabulary.

**Configuration and one persisted context.** Optional `newcomers: { later: [person-key] }`
in configure/attributes.yaml names declared Persons, each once. Unknown/non-Person keys
are UnknownPerson; duplicates are DuplicateNewcomer. A profile is optional: fixed values
and defaults still apply. Deferred people exist from assembly but receive no traits-stated
or attributes-handed at genesis. CLI resolve lists them as deferred without values.

The finalized attributes context contains the complete deferred-key → Fixed map before
seeding. Fixed retains authored/ruled/locked values and restrictions; authored values take
precedence over locks. The existing single attributes-composed event carries optional
newcomers { profile, seed, salt, deferred }. Its owner starts attributes-newcomers, an
uninterruptible Process containing that context and an initially empty arrived set.
There is no awaited event, lazy initialization, mutable shared context or missing-map
fallback. With no newcomers block, the new field is omitted and prior bytes are unchanged.

**Admission and ownership.** A creator declares `uses: { admits: true }` in its System
Pack's attributes data, depends on attributes and declares the borrowed NewcomerAdmitted
vocabulary (ARC-26). World/Entity Pack data cannot grant admission rights. The creator
calls check_newcomer in validate, emits its own recorded cause, then calls admit_newcomer
with that cause. NewcomerAdmitted { person, because } is SystemInternal. Only attributes
draws and states values. It rechecks authorization, deferred membership, prior arrival,
draw satisfiability and that the cause precedes the request. Failed rechecks stop the
world with FactRefusedByOwner; ordinary invalid actions belong in creator validation.

The owner reads only plain Traits from Persons already present, ordered by entity ID;
it never copies another owner's state. It updates arrived before returning emissions so
a same-generation duplicate is refused. It always emits traits-stated, including an
empty plain value list, then attributes-handed per owner in owner order. All are in the
same dispatch/journal revision. TraitsStated is holder-only; handoffs are SystemInternal.
A proposal about a deferred person is not-arrived until admission. Before arrival no
traits are disclosed; afterward the existing per-observer filter controls disclosure.

**Sampling.** Reuse genesis words keyed by seed, salt, attribute and person key. The
causing EventId is diagnostic, never mixed into randomness. Fixed values are not redrawn.
Parents and resident values are resolved/derived at arrival time. For stratified plain
categories, choose against nonnegative integer deficits `(n+1)*weight - 1_000_000*count`,
respecting masks/restrictions and falling back to permitted row weights when deficits
are all zero. Stratified numeric attributes use ten profile-decile bins, the same deficit
selection and a word for the quantile within the selected bin. Independent distributions
and owner-held attributes use independent row draws. Birth is relative to arrival time;
roles, defaults and covers:adults retain their established order. All arithmetic is integer;
input has no name, note, persona, wall clock or run seed.

**Refusals.** Checked admission reports attributes-uncomposed, no-newcomers,
not-an-admitter, not-a-newcomer, already-arrived or newcomer-unsatisfiable with the person
identified. The owner additionally refuses unknown-cause. Context seeding fails
newcomers-unresolved when configured and finalized deferred key sets disagree.

**Persistence and limits.** Replay reexecutes journaled admissions and compares bytes;
snapshot restore does not independently sample. Before resume, the host compares actual
disk genesis context against freshly finalized context; authored/locked/restricted values,
profile, seed, salt and deferred-list edits are drift. Runtime facts are not genesis
configuration. Internal composed context contains the resolved profile and fixed-origin
classification needed for future draws; public trait facts disclose neither sampling
origins nor profile/lock metadata. Two distinct same-generation admissions see the same
pre-reduction population, as frozen. A creator that emits no request at all is invisible
to attributes; scenario completeness tests must detect it.

**Validation status.** The fixed S30-j statistical acceptance is not amended by this record.
F-S30j-10 in the PR ledger records a measured conflict between its every-declared-row
quota wording and explicit independent distributions. The counterexample and proposed
acceptance clarification remain pending operator decision; implementation is not ready
on that criterion. No sampling flag, threshold or seed has been changed to hide it.

**Reuse and revisit.** This extends the existing integer sampler, checked-owner request
pattern and persistence engine; it adopts no dependency. A separate sequence index or
count cache is unnecessary. Revisit when QPL-11 grants runtime creation, a departure
System defines population membership, or an owner supplies authoritative counts for its
own attributes. Do not widen those contracts in S30-j.

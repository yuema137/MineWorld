## ARC-113 — An optional authored reference value per item kind, never charged

**Date** 2026-10-18 · **Approved by** the operator: step-31 (approved 2026-10-15) and the S31-a PR design's
Q-S31a-2 (2026-10-15), frozen 2026-10-18 · **Implements** [`CORE_CONCEPTS.md`](../CORE_CONCEPTS.md) §7 note,
[`MODULE_SPEC.md`](../MODULE_SPEC.md) §4.1 · **Relates to** `ARC-36`, `ARC-111`, `ARC-112`, `ARC-114` ·
**Design** `.structured-coding/plans/mvp0/step-31-wealth-prices.md` §6

**Problem.** A wealth estimate and a pricing policy's default need a typical worth per kind, and nothing in the
world held one. Deriving it from trades would make economy an aggregator and let controllers read trades they
never perceived.

**Choice.**

1. An item file may carry `economy: { reference: <amount ≥ 1> }` (economy's section now also carried by Items,
   as `ARC-36` extended `ARC-31`). It seeds `reference-declared { item, value }`, `SystemInternal` (Q-S31a-2),
   reduced into `ReferenceValue { value }` on the item kind. An item file's `economy:` may carry nothing else
   (`economy-item-reference-only`); a Person or Organization may not carry `reference`
   (`economy-reference-on-holder`).
2. It reaches observers only through `ARC-111`'s `currency` record, whose `references` list every kind with one,
   in item order: a typical worth is common knowledge and reveals nobody's state.
3. **It is never charged.** No path of `buy`'s `validate`, `resolve` or reduction reads it (I-S31-6). Its uses
   are the wealth view (`ARC-114`), a pricing policy's default and bounds, and context for cognition.
4. It is authored, not derived. A value derived from trades is a suggestion, which is a reporter's notice, never
   world truth.

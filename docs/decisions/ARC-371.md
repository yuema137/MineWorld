## ARC-371 — Packaged play converses through a locally installed cognition runtime (R1), supervised by the launcher; a bundled private Python (R2) is prototyped later

**Date** 2026-11-27 · **Status** accepted (design frozen; implemented by dialogue PR-B) · **Approved by** the operator, 2026-11-27, relayed by the primary coordinator: "同意三个都按推荐冻结" (design `pr-playable-dialogue-memory.md` DM-20261127-3, Q-D1 … Q-D5 as recommended; bounded resolutions B1–B3) · **Relates to** `ARC-56`, `ARC-57`, `ARC-59`, `ARC-72`, `ARC-73`, `ARC-78`, `ARC-84`, `DEP-26`, `DEP-58`, `DEP-61` · **Design** `.structured-coding/plans/mvp0/pr-playable-dialogue-memory.md` §§0, 3, 4; specifications [`../reference/cognition-supervised.md`](../reference/cognition-supervised.md) and [`../../tools/launch/LAUNCHER.md`](../../tools/launch/LAUNCHER.md) §10

**Problem.** The operator's playable MVP asks that a player can talk to a resident and be remembered across
leaving, rejoining and a restart (`operator-playable-mvp-20261123.md` check 2). The LM Controller is a Python
Controller Pack (`ARC-72`); the downloadable bundle is a Rust launcher, a Rust server and exported Godot clients
(`ARC-78`, `ARC-80`) and ships no Python. Something must provide the cognition process's Python runtime in packaged
play, without making any world, client or test depend on it: a world with every model removed stays a valid world.

**Options considered.**

| Option | Verdict |
| --- | --- |
| **R1 — a locally installed runtime:** the interpreter of a MineWorld source checkout's `uv sync --locked` environment on this machine, named by the player's per-user profile, checked against a runtime manifest before each run; missing or stale ⇒ rule-only play with a named reason | **Chosen** (Q-D1), labelled "requires local runtime", never "self-contained" |
| R2 — a private Python inside the bundle | Deferred to its own prototype PR (candidates below); not decided here |
| Start a model service or download a model from the launcher | Declined: the launcher never downloads a model or runtime and never starts or stops a model service (Q-D1; `ARC-78` keeps it a process supervisor) |
| The Godot client or the server hosting cognition | Declined: clients stay protocol clients and the server never imports an LM concept (`CLAUDE.md` §4 rule 3) |
| A new agent-memory framework for the remembered exchanges | Not reopened: `ARC-59` and `DEP-58` already declined Letta, mem0, Zep, Graphiti and LangGraph memory in favour of the controller's SQLite home |

**Choice.**

1. **Profile.** Conversation is on only while `<user dir>/cognition/profile.toml` exists. It uses `launch.toml`'s
   grammar and parser (`ARC-78`), and adds four keys per mode, all or none: the interpreter, the operator's
   cognition configuration, the runtime manifest (absolute), and the bundle-relative decision list. The bundle
   ships an inactive, commented template and `runtime/decisions/market-town-alice-lm.yaml` (Alice on `lm`, fallback
   `rule`). Profile and stores live in the per-user folder, so they survive package upgrades and read-only bundles
   (B2).
2. **Runtime check.** `python -m mineworld_cognition --write-runtime-manifest` records the interpreter's Python
   version, the checkout's revision and `uv.lock` digest, the source files of `mineworld-cognition` and
   `mineworld-sdk` as imported, and every other installed distribution by name and version (checked against the
   lock). `--preflight` re-derives and compares it, checks that the entry-point groups resolve, that every bound
   backend is on loopback, and that the local service lists the configured model (a listing; no inference). Any
   difference ⇒ the world plays rule-only and the launcher's log says why. Updating the checkout requires writing
   the manifest again.
3. **Supervision.** The launcher runs the interpreter directly (`-I`, no shell, no `uv run`) as
   `--supervised`, after the server's join line, with an environment it builds itself: no admin capability, the
   invite only in `MINEWORLD_INVITE`. It reads only a versioned status line with a closed reason set; it stops the
   child by closing its standard input, before the server, and kills only that owned child past a bound. Clients
   and the world never wait for inference.
4. **Stores.** One store per world, `cognition/<world>/`, created by the launcher and deleted with the world's save
   by `--fresh` (B1); the cognition process binds it to one world instance and refuses another.
5. **Platforms.** The launcher's child lifecycle is built and tested on macOS, Linux and Windows (a scripted
   process; the real process in the `python` layer). The R1 delivery and the live check are this Mac only; live
   conversation on Linux and Windows is not claimed (B3).

**R2 candidates to prototype later** (each question open until that prototype answers it): python-build-standalone
(a relocatable CPython plus the locked closure), PyInstaller, Briefcase. Open questions for each: provenance and
redistribution terms of the interpreter and every wheel; relocatability of the bundle folder; native wheels
(`pydantic-core`, SQLite) per target; a universal macOS build; download size against the bundle budget; signing and
notarisation.

**Consequences.** Packaged conversation works only where a player has set up R1; everywhere else the same bundle
plays rule-only with a clear message, which is the required behaviour of a world without models. The launcher grows
one module (`tools/launch/src/cognition.rs`) and reads no JSON library: the status line is four flat keys read
strictly, as `launch.toml` is. No kernel, System, protocol or World Pack contract gains an LM concept.

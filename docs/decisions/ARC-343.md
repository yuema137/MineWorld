## ARC-343 — Which facts a 2D client shows, and how, is the Presentation Pack's

**Date** 2026-10-20 · **Status** accepted · **Approved by** the operator's freeze of PR 13e (2026-10-20, Q-13e-3, Q-13e-4) · **Relates to** `ARC-46`, `ARC-70`, `ARC-47` · **Design** `.structured-coding/plans/mvp0/pr-13e-many-players-2d.md` §5.3 (SD-13e-3)

**Problem.** Since S11-C every observation carries the facts its observer learned (`observation.events`, `server/PROTOCOL.md` §5.2). A player should see a line spoken near them and an activity starting near them. If the client named `spoke` or `group-activity-started` in its code, a world with other systems would need a client change, and the client would hold world vocabulary (step-13 I-13e-2).

**Choice.**

1. The Presentation Pack's `renderer/godot.yaml` gains an `events` table (`clients/2d/PRESENTATION.md` §4.1): event type → `{ "show": "bubble", "text": <payload field> }` or `{ "show": "notice" }`, plus `bubble_seconds` and `notice_seconds`. A type the table does not name is not shown and is counted as skipped; it is never an error.
2. A bubble is drawn over the envelope's first subject (`subjects[0]`), the contract's "what the fact is about". A notice is worded by the key `ui.event.<event_type>` with `{who}` (the subjects' names) and the payload's top-level string and whole-number fields.
3. The source is `observation.events` of every frame, de-duplicated by event `id` per world instance, not the reliable `perceived` stream: bubbles are about now, and a backfill after a rejoin would replay old lines.
4. `scripts/check_client_rules.py` R8 holds every event type and field named in the default pack's table out of the 2D client's scripts.

**Bounded deviation from the design text.** The design named the wording key `event.<type>`. The catalog checks (`tests/acceptance/tests/client_text.rs`, `KEY_FAMILIES`) admit only known first segments, and `event` is not one, so the key is `ui.event.<type>`. Same meaning; no test outside the client's paths changes.

**Consequences.** `social-cafe` and `lakeside` show bubbles and notices with no client change, because they install the same systems. A world with other systems is shown by editing a pack table. A future event whose first subject is not the person to draw it over needs a `who` field in the table (risk RK-13e-3).

**Revisit** when a 3D client shows events (lift the table to a shared presentation schema), or when an event type needs a subject other than `subjects[0]`.

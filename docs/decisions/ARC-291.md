## ARC-291 — CI launches of the 3D slice render cheaply: `--aniso=off`, `--render-cost=low`, streamed output and a cached shader cache

**Date** 2026-10-18 · **Status** accepted (operator approval of the fix PR, 2026-10-18) · **Relates to**
`ARC-149`, `ARC-102`, `.structured-coding/plans/mvp1/inv-f13c-impl-5-software-renderers.md` (the
investigation record; its §5 is this decision's design), `.structured-coding/plans/mvp0/pr-13c-nightly.md`
§12.2 (F-13c-impl-5)

**Problem.** The investigation record (§3) found four causes for the 3D slice being slow or broken on the
hosted runners:

1. The hosted macOS GPU (Apple Paravirtual) has no argument-buffer tier 2, so Godot 4.7.2 compiles shaders
   for slot binding, where Metal allows samplers 0–15. The material samplers sit at slot
   `6 + filter + 6·repeat`, so the two anisotropic **repeat** samplers are at 16 and 17. Every shader that
   uses one fails to compile (784 lines `must be between 0 and 15` on nightly 39134198789): the slice's
   paving, walls, roofs and hair were not drawn there, and each launch compiled them again.
2. A cold runner compiles every Forward+ pipeline before the first frame (the ARC-149 warm-up took 373 s).
3. On a software rasteriser (lavapipe, D3D12 WARP) a frame of the full look costs well over 20 s, so SET-b's
   connected 3D settings tests drew fewer than 12 frames in 240 s and were skipped there (ARC-149).
4. The Rust harnesses echoed Godot's output with `eprintln!` from a reader thread. libtest captures that
   and drops it when the test passes, so a slow run and a hung one both showed nothing for 40 minutes.

**Decision.**

1. **One texture filter, `Mats.FILTER`** (`clients/3d-spike/scripts/mats.gd`). It is anisotropic for
   players. With `--aniso=off` on the command line it is `TEXTURE_FILTER_LINEAR_WITH_MIPMAPS` (trilinear).
   Every repeating material uses it (`Mats.pbr`, `Mats.card`, `palette.gd`, `profile.gd`), and the hair
   shader is loaded through `Mats.shader`, which rewrites its `filter_linear_mipmap_anisotropic` hints to
   `filter_linear_mipmap` under the same switch. The switch is a flag that the launch passes, never a guess
   from the adapter's name: a check must not silently judge a different picture on a different GPU.
2. **`--render-cost=low`** (`slice_main.gd`). It multiplies the settings' render scale by 0.5
   (`MineWorldDisplay.render_scale_factor`; the settings value and its file are unchanged), takes GI none,
   and turns off directional shadows, SSAO and glow. None of these is judged by a scripted check. The
   far-field check keeps its own 1 440 × 240 SubViewport and its frozen viewpoints.
3. **Every CI and harness launch of the slice passes both flags**: `scripts/ci_godot.py` (`SLICE_CI_FLAGS`,
   for the probes and the ARC-149 warm-up) and the Rust harness (`godot2d::SLICE_3D_CI`, for the connected
   settings and controls tests). The rendered far-field check passes `--aniso=off` only; it already turns
   its own cost effects off (R-FF-1 (b)). The settings test that reads the window's render scale expects
   the file's value times 0.5.
4. **SET-b's three connected 3D settings tests run on Linux and Windows again**: their QC-5 skips are
   removed from `SKIPS`. `HOSTED_UNRUNNABLE` and `QC5B_RULED` are unchanged.
5. **Streamed output.** The 3D harnesses print Godot's lines through `godot2d::echo`, which writes to the
   stderr handle; libtest does not capture that. The far-field check prints one
   `[farfield] progress: viewpoint <name> at <s> s` line per viewpoint.
6. **The macOS shader cache is kept between nights.** The nightly `clients-mac` job restores and saves
   `~/Library/Application Support/MineWorld/{shader_cache,vulkan}` (the project's `custom_user_dir`),
   keyed by `scripts/ci_godot.py` (the Godot pin), the `.gdshader` files and the 3D client's scripts, with
   one entry per run and the newest restored.

**Consequences.** Players see no change: without the flags every value is what it was. A check in CI judges
the slice drawn with trilinear filtering, at half render scale and without the cost effects; what it judges
(where things are, what the HUD says, what the server receives) does not depend on any of them. If a
re-enabled test still fails on a software renderer, its skip comes back with the measured reason.

**Evidence.** Recorded in the PR that lands this record.

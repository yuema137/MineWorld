## ARC-374 — The single-player advance: a host operation that runs a sleeper's night, stopped by a pack's adapter

**Date** 2026-11-27 · **Status** accepted (operator rulings Q-L3, Q-L4 option A, 2026-11-27, "同意三个都按推荐冻结";
lifecycle implemented in PR N2-C2, the exact-due loop in N2-C3, branch `mvp0/pr-nightlife-n2`) · **Amends**
`ARC-69` item 5 · **Relates to** `ARC-25` (saves), `ARC-27` (no controller state in a save), `ARC-40` (host
state), `ARC-42` (hosted controllers), `ARC-44` (the admin surface), `ARC-62` (extension catalogs), `ARC-69`
(the host clock and journal), `ARC-373` (`sleep-until`) · **Design** `.structured-coding/plans/mvp0/pr-nightlife.md`
§§0, 3 (N2-I3 … N2-I14), 6 (N2-C2, N2-C3)

**Problem.** In a single-player world a player who goes to bed should not wait eight wall hours, or forty wall
minutes at the default scale, for morning. Raising the scale (`ARC-69` item 5) is not the answer: it changes every
hosted cadence's wall meaning, cannot stop at an earlier wake, and has no identity a killed client can reconnect
to. Skipping to morning is not the answer either: every resident, Process and event in between must really happen,
in order (Q-L3).

**Choice.**

1. **The advance is a host operation, not a world rule.** `POST /admin/advance { operation, seat, until }`
   (`server/PROTOCOL.md` §11.4). No field names an instant (`ARC-40`). It is never a fact, an input or a revision,
   and never a rescale: the scale in force is unchanged before, during and after.
2. **Admission (N2-I3, Q-L4 option A).** Only in a world started `--solo`; only for a seat driven by exactly one
   connection while **no other seat is connected or held** (hosted and free seats may be anything — an LM-driven
   or second human seat refuses it, `other_controller_connected`); only while the clock runs, no other advance
   runs, the world has the adapter, and the seat's Person is in the adapter's state, identified at the start. Each
   failure is a named refusal before anything is recorded.
3. **A generic server; the stop is a pack's (N2-I4).** The server knows the trait
   `mineworld_sdk::advance::AdvanceStop` — `identify`, `horizon`, `holds`, each a read of authoritative state —
   and finds an adapter by name in a write-once process catalog registered by one `extension` line of the
   installed set (`ARC-62`). The sleep pack implements it (`"sleep"`: an occurrence is one sleep's Process, its
   horizon the alarm, and it holds until the sleep ends however it ends). A world in which the adapter's system is
   not enabled refuses `unknown_adapter`. The trait lives in `mineworld-sdk` because it must read `&World` (the
   contracts crate depends on no kernel) and the kernel is not changed; neither `mineworld-server` nor `tools/cli`
   names a pack.
4. **Durable identity (N2-I8, N2-I9).** The client generates a 128-bit operation id. The lifecycle is two host
   records in a table of its own, `host_operations`, created lazily: `advance_started { operation, seat, adapter,
   prior_scale }` before the first instant and `advance_ended { operation, outcome, reason }` after the last.
   `PacingChange` is unchanged and there is no `SAVE_FORMAT` bump: a pre-N2 binary reads past the table as a
   pre-TW-c binary reads past `host_journal`. `verify` checks the table's coherence and never re-executes it. A
   repeated id with the same payload answers the recorded status; with another, `operation_conflict`.
5. **Ends (N2-I10).** `woke`, `cancelled` (the server submits nothing; the sleeper stays asleep), `disconnected`
   (with `reason: lagged` when delivery released the sleeper), `stopped`, `interrupted` (recorded at the next start;
   nothing resumes automatically, `ARC-69` item 8), `failed` (a record or commit the save could not take stops the
   world; nothing partial is retried or reported as morning).
6. **While one runs (N2-I12).** Joins and other connections' submits are refused `advance_in_progress`; clock
   changes and kicks or releases of anyone but the sleeper are `409 advance_in_progress`; losing the sleeper's
   connection ends it `disconnected`; a stop ends it `stopped`. The ticker's sweep only sweeps.
7. **Execution (N2-C3).** The exact-due loop visits, in the ordinary order, every instant at which the kernel or a
   hosted controller is due, up to the adapter's horizon, and stops at the first completed instant at which the
   occurrence no longer holds. Its parity with the ordinary host driven at every due instant is the acceptance
   (N2-I6). Until N2-C3 lands, an admitted advance records its start and ends at once `stopped { not_yet_executable }`.

**Amendment to `ARC-69` item 5.** Item 5 said "`--solo` selects no code path … it only widens one permission".
After this record: **`--solo` widens two permissions — scales above 24, and the advance operation; the advance loop
is reachable only through the second; world rules, authority and persistence remain one path.** Shared worlds never
advance and never jump time (step-35 Q-S35-9 stands for them).

**Rejected.**
- *A rescale as the advance.* It changes every hosted cadence's wall meaning, cannot stop at an earlier wake, and
  needs a client to restore the scale it raised.
- *New `PacingChange` variants for the lifecycle.* `PacingChange` is `Copy` and pinned; a pre-N2 binary would fail
  to decode the host journal. A separate lazily created table is ignored by it instead.
- *The trait in `mineworld-contracts`.* The adapter reads the world; contracts depend on no kernel.
- *A sleep check in the server.* It would put a domain rule in the kernel's neighbour, against `CLAUDE.md` §4
  rule 2 and the change-amplification test.
- *Temporarily rebinding other minds to rule controllers (Q-L4 option B).* A change to seat ownership; deferred to
  its own PR (N3) after the dialogue lane freezes.

**Revisit trigger.** S21's "doze" during a ride (QRT-7) may adopt this operation with another adapter instead of a
rescale; a multiplayer advance would need a consent model and is out of scope.

**Consequences.** A client offers "sleep until 07:00" from the sleep pack's complete offer and, in a `--solo`
world with an admin token, then requests the advance with a fresh id, reads progress from `clock` frames and its
own observations, cancels or wakes through its own session, and after a reconnect polls the status by id rather
than resubmitting (N2-C4).

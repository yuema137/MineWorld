## ARC-175 — Every world that ships a 3D depiction ships one recorded MCP scenario with a 3D observer, run in CI

**Date** 2026-10-26 · **Status** proposed in PR S33-i ("An MCP agent plays Lakeside like a person, and a 3D
client sees it"); pending the operator's merge review · **Relates to** `ARC-144` (any world on the same
server path), `ARC-105` (role tags), step-27 (agents are first-class players), step-33 AC-S33-8,
`.structured-coding/plans/mvp0/pr-s33i-agents.md` §§5.1–5.3

**Problem.** An outside agent plays through the MCP adapter, and a person plays through a client. Both reach
the same server and the same rules (step-27). Nothing checks that the two meet in one world: that a walk an
agent decides is the walk a 3D client draws. Without such a check, an agent path could drift from the human
path world by world, and nobody would notice until a person watched an agent walk through a wall.

**Options considered.** (A) One recorded scenario per world with a 3D depiction: a deterministic MCP script
plays a seat, a real 3D client watches from another seat, and the server's facts are the oracle (chosen).
(B) Check only the agent side headless and trust the 3D client's own probes (rejected: it never puts the
two on one server). (C) Drive the scenario with a live model (rejected: not deterministic, and `CLAUDE.md`
§4 item 10 forbids it in core tests).

**Decision.**
1. A world that ships a 3D depiction (`clients/3d-spike/scripts/depictions/`) ships one recorded MCP
   scenario: a deterministic script, no language model, that joins a seat through the MCP adapter, finds its
   way from what it observes (role tags and exits, never a place key), and walks between places with
   `act { kind: walk_to }`.
2. The same scenario runs with a real 3D client joined on another seat of the same server, standing where it
   can perceive the agent. The client writes what it draws (`--observe-log=<file>`: per observation, each
   drawn figure's entity id, bound place and position). The test compares the agent's place changes the
   server recorded (`person-entered-place` facts in the save) with the figure's appearances and
   disappearances in the observer's log: same order, each within 2 s of world time.
3. Only what the observer can perceive is compared. Presence shows an observer its own place and the people
   in it, so the observer's place decides which crossings are checked. That is the world's rule, not a gap.
4. The agent half runs in the agent suite on every platform; the 3D half runs where the nightly Godot layers
   run (`clients`). Lakeside's is the first: `clients/agent/tests/test_play_lakeside.py` and
   `tools/cli/tests/agent_with_3d_observer.rs`.

**Consequences.** Agents and humans are checked on the same path, world by world. A new world with a 3D
depiction carries one more test file pair. The observe log is a log only: it changes nothing the client
draws or sends.

**Revisit** when a second world gains a 3D depiction (it adds its scenario), or when the 2D client should be
an observer too.

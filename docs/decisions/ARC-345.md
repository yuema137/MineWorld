## ARC-345 — The 2D launcher hosts a living town by default and assumes no seat or agent

**Date** 2026-10-20 · **Status** accepted · **Approved by** the operator's freeze of PR 13e (2026-10-20, Q-13e-5, Q-13e-7) · **Relates to** `ARC-344`, `clients/shared/HOST.md` §§5–6 · **Design** `.structured-coding/plans/mvp0/pr-13e-many-players-2d.md` §5.4 (SD-13e-4)

**Problem.** `./mineworld-2d` defaulted to `--seat carol` and `--agent alice`. Neither exists in `worlds/lakeside`, so the default launch failed on any world but market-town and social-cafe. The town did not live: only Alice answered, and only when spoken to. A second player on the same machine had to dig the invite out of the server's log.

**Choice.**

1. No default seat and no default `--agent`. Without `--seat` the client shows its join screen, filled from the world's `GET /status`.
2. A played hosted run starts the server with `--town` (every seat no player holds is driven by the paced rule controller), as `mineworld-slice` does. `--no-town` hosts a quiet world. `--agent <seat>` still drives one seat reactively. Scripted runs (`--drive`) keep their explicit arguments and no `--town`, so every existing test is unchanged.
3. `./mineworld-2d --join-local` opens a second window on the world this checkout hosts for `--world`: it reads that server's join line from `clients/2d/.save/server-<world>.log` itself and hands the address and invite to the client. It starts no server and prints no invite.

**Consequences.** Every world with seats is played with one command. The invite stays out of the terminal (`I-13e-5`). LAN hosting from the launcher stays out of scope (it hosts `--solo`).

**Revisit** when the launcher hosts on a LAN, or when the town controller is chosen per world in the World Pack.

## ARC-184 — Clients format money and read trade records through one shared module

**Date** 2026-10-20 · **Status** accepted (S31-e PR design frozen by the operator 2026-10-20, Q-S31e-1 … 4 as recommended); implemented by S31-e · **Approved by** the operator, directly in the primary session · **Relates to** `ARC-34`, `ARC-47`, `ARC-70`, `ARC-111`, `ARC-112`, `ARC-114`, `ARC-115` · **Design** `.structured-coding/plans/mvp0/pr-s31e-clients.md`; `clients/shared/TRADE.md`

**Problem.** After S31-a the world discloses its currency: a name, a symbol, which side the symbol goes on, and how many digits of an amount are minor units (`ARC-111`). Both reference clients ignored it and divided every amount by 100 with two decimals, each with its own code (2D `hud/words.gd`, 3D `SliceThings.money`). A world whose money has no minor units showed "0.03 cr" for three crowns. The two clients also read the wallet and the shop listing with two copies of one reader (16d Q-16d-5). Step-31 §12 requires one formatter and one panel model, so that no game logic is duplicated between the 2D and 3D clients.

**Options considered.**

| Option | Verdict |
| --- | --- |
| Put the formatter and readers in the settings module, beside the clock formatter | Declined: the settings module is about the player's settings and wording; trade records are one pack family's shapes |
| Put them in the protocol module (`clients/protocol/mineworld`) | Declined: the protocol module reads frames for any game and stays game-neutral (16d ruling 4) |
| Keep two client-local readers and formatters | Declined: two copies of one rule drift (F-S31e-1 is exactly that), and step §12 forbids it |
| **A new shared module, `clients/shared/trade`, symlinked into both clients as `res://mineworld_trade`** | **Chosen** (Q-S31e-1 (a)) |

**Choice.**

1. **`MineWorldMoney`** formats an integer of minor units from the disclosed currency only: grouped in threes, the exponent's digits after the decimal mark, the symbol on the world's side; the marks and spacing are wording keys (`format.money.*`). With no currency disclosed an amount is the bare integer. It parses a typed price back to minor units, checking representation only.
2. **`MineWorldTrade`** reads the trade records (`currency`, `wallet`, `wealth`, `holdings`, `asks`, `shop`, `item-catalogue`, `notice-board`, `subscriptions`) and builds the rows both clients draw. A priced offer is recognised by its shape (a complete affordance with an integer `price` and a typed `item`), never by its action type. The seller actions a client composes come from that client's own table in its `intents.gd`, the only place a type is spelled.
3. **No client decides.** The module and both clients compare no money, read no reference value and compute no expiry; a row the server marked unavailable is shown and still pressable. `tests/acceptance/tests/client_rules.rs` holds this as check e.

**Consequences.**

- 13b's `format.money` key is retired; 16d's two readers of `wallet` and `shop` read through the module's formatter. R-16d-7's open duplication is closed for the trade shapes.
- A new priced action (S31-h's haggling, a future auction) shows in both clients with no client change; a new seller action needs one table entry and one payload case in each `intents.gd`.
- Both launchers and the nightly Windows symlink checks list the new module.

**Revisit** when a world needs a number format the marks cannot express (an Indian grouping, a currency with a non-decimal minor unit), or when a third client appears.

## ARC-350 — Offers are ordered by the category each pack declares for its actions

**Date** 2026-10-20 · **Status** accepted (operator ruling 2026-10-20, relayed by the coordinator;
implemented in PR #413) · **Relates to** `ARC-34`, `AC-12`,
`.structured-coding/plans/mvp0/pr-s27-g-offer-order.md`

**Problem.** An observation listed its affordances in the order perception produced them: by target
(offers with no target first, then one block per present entity), and inside each target in the order the
World Pack composed its providers. That order says nothing about what matters to a person entering a place.
When S31-a's economy actions reached the default town, they filled the first window of the agent view's
`offers`, and `talk` was pushed to page 2.

**Choice.**

1. `mineworld-contracts` gains a closed enum, `ActionCategory { Social, Interaction, Commerce }`. Its variants
   are declared in rank order, so `Ord` is the rank. The `Action` trait gains
   `const CATEGORY: ActionCategory`, which defaults to `Interaction`. The pack that defines an action declares
   its category next to `ACTION_TYPE` and `OWNER`. The category is read off the type, so an offer cannot carry
   another action's category.
2. The default is `Interaction`. An undeclared action ranks after social acts and before commerce, so no
   existing pack has to change and a forgotten declaration stays in the middle.
3. The order is applied once, on the server, in presence's `observe`. Each `Offer` records `A::CATEGORY`. The
   priced affordances are then **stable**-sorted by category, so inside one category the previous
   deterministic order is kept (by target, then composition order, then each provider's own order). Replay
   comparison (`AC-12`) still holds.
4. The order never compares action names. The wire format is unchanged, because an `Affordance` carries no
   category; the order of the list is the information.
5. Every client (the agent view and MCP adapter, the 2D menu, the 3D client) uses the observation's order
   as it arrives, so one sort serves all of them.

**Kernel ignorance.** The kernel never reads the category. It is a declared vocabulary for ordering what an
observer is offered, not a rule about money or conversation. A finer order is a later change to this enum,
reviewed as a contract change.

**Rejected.** A pack manifest field mapping action names to categories. It would be a second table keyed
by strings, and it could drift from the actions it names.

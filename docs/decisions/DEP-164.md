## DEP-164 — The macOS bundle renders through Vulkan (MoltenVK), not Godot's Metal driver

**Date** 2026-11-27 · **Status** accepted · **Approved by** operator ruling of 2026-11-27 ("换 Vulkan；用 CI 测"),
relayed by the primary session · **Relates to** `DEP-45` (the pinned Godot), `ARC-80` (the bundle layout), step-23
PR S23-RT (the shared runtime) · **Design** `.structured-coding/plans/mvp0/pr-startup-loading.md` (perf findings)

**Problem.** A player's first launch of the packaged 3D client took about 2.5 minutes to reach the first view.
Measured on an Apple M5 with macOS 26.2 and the official Godot 4.7.2 (evidence: `perf-startup/target/perf-evidence/`,
`comparison.txt`):
- **Cause.** Godot's own Metal driver compiles every shader variant from MSL source when it loads them (its
  "eager" strategy). It keeps no pipeline cache of its own: `pipeline_cache_create` is stubbed out in
  `rendering_device_driver_metal.cpp`. So the cost depends entirely on the OS's Metal compiler cache for the app.
  With a cold cache (a first launch, a new export whose shaders changed, an OS or GPU-driver update, or eviction),
  the first frame through the player's camera blocked for 117–122 s.
- **Cold vs warm, same build.** First view at 164 s cold (median of 3) and 12–14 s warm.
- **Upstream.** godotengine/godot#106757 (open) reports the same thing.
- **Workaround ruled out.** The driver's lazy strategy (`GODOT_MTL_SHADER_LOAD_STRATEGY=lazy`) hung here, and
  upstream reports artifacts and crashes with it (#115064).

**Options compared.**

| Option | Measured | Verdict |
| --- | --- | --- |
| **Vulkan through MoltenVK** (in the official macOS templates, statically linked) | Cold first view 42.9 s (median of 3, unpackaged) and 47.5 s (packaged, median of 3); warm 12.6–14.8 s; Godot persists its Vulkan pipeline cache (`user://vulkan/`); pipelines compiled identical (canvas 2, mesh 41, surface 109, specialization 126); steady FPS 145 on both (the same cap); matched stills: PSNR 49 dB away from the HUD, 0.006 % of pixels differ by more than 3 % | **Adopt.** About 3.5× faster cold start, the same picture, the same Forward+ renderer and settings. |
| Godot's Metal driver (default) | Cold 164 s, warm 12.4 s | Rejected for now: the first launch is unplayable. |
| Metal plus Godot's shader baker (`.metallib` built at export) | Exported on a GitHub `macos-26` runner with Xcode's Metal toolchain (scratch run 46116742033: 333 + 613 bake steps, no "limited to SPIR-V"). Cold first view 149 s, then twice no first view within the 240 s watchdog; the join frame still blocks for at least 117 s, and only opening the pack got faster (about 1.4 s instead of 6–13 s). Warm 14.4–15.0 s | Rejected for now: the remaining cost is backend pipeline compilation, which baking does not remove. |
| Hide the cost (prewarm in the launcher) | Same total | Rejected: it moves the wait, it does not shorten it. |

**Choice.** `clients/runtime/project.godot` sets `rendering/rendering_device/driver.macos="vulkan"`. The shared
runtime is the engine of both clients, so packaged 2D and 3D both render through Vulkan on macOS. Windows and
Linux are unchanged. Source runs of `clients/3d-spike` (the editor, harness probes) keep that project's default
(Metal). A client's run-time settings cannot carry the driver (S23-RT: the driver is chosen before a pack is
mounted).

**Way back to Metal (one line).** In `clients/runtime/project.godot`, set
`rendering_device/driver.macos="metal"` (or delete the line) and re-export. To compare without a rebuild, start
the runtime directly with `--rendering-driver metal`. The launcher takes no engine arguments (`LAUNCHER.md` §3),
and `Contents/MacOS/` must hold exactly one file, so an `override.cfg` there is not a player-facing option.

**Revisit when** Godot persists Metal pipelines (#106757 or a binary-archive cache), or when Vulkan shows a visual or frame-rate regression
on any supported Mac.

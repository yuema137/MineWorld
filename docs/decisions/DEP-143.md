## DEP-143 — Rigid overlap between many objects: trimesh with python-fcl, behind `mwcast/contact.py`

**Date** 2026-10-19 · **Status** proposed (DRAFT; awaiting the operator's freeze of step 36) · **Approved by** — (research plan approved 2026-10-19; takes effect at the step's freeze) · **Relates to** `DEP-13`, `DEP-142`, `DEP-145`, [`REUSE_POLICY.md`](../REUSE_POLICY.md) · **Design** `.structured-coding/plans/mvp1/step-36-interpenetration.md` §§4.1, 4.5; `pr-s36-p1-contact-module.md` commit 4

**Problem.** Items must not sink into the floor or into each other, and a drawn furniture mesh must lie inside the
`Solid` the server resolves people against. That is a question about many rigid objects at once: "which pairs touch,
how deep, and how far apart are the rest?" libigl (`DEP-142`) answers point-in-mesh questions for one pair; it has no
broadphase over a scene.

**Choice.** Adopt **trimesh** (MIT; 5.1.1, 2026-10-02) with **python-fcl** (BSD-3, wrapping FCL, BSD-3; 0.7.0.11,
2026-04-08). trimesh loads a glTF scene with its node transforms; `trimesh.collision.CollisionManager` adds each part
and reports `in_collision_internal(return_names=True, return_data=True)` (pairs and contact depth) and
`min_distance_internal`. Pinned in the root dev dependency group and the tooling requirements; imported only by
`mwcast/contact.py`.

**Why this and not another.** Wheels exist for every platform we support (python-fcl: macOS x86_64 and arm64,
manylinux x86_64 and aarch64, win_amd64, cp39–cp314). Coal is technically stronger for convex queries but has no
Windows wheel on PyPI (`DEP-145`). The server's own shapes are integer boxes, so the authoritative layout test stays in
Rust on the `bodies` pack's geometry, with no new dependency (step 36 §4.5); trimesh is for the drawn meshes only.

**Limit, accepted.** FCL's mesh–mesh depth is per triangle pair, so it is reliable as a yes/no and as a distance and
weak as a volumetric depth. The gates use it for rigid items, where a yes/no with a local depth is enough.

**Consequences.** Tooling only; never a runtime dependency. trimesh may pull its own optional extras; only the base
package and python-fcl are installed.

**Revisit** if python-fcl stops shipping a wheel for a supported platform, or if Coal ships one for Windows on PyPI.

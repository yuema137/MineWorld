## ARC-111 — The currency is economy configuration: one per world, ISO-4217-shaped, required with economy

**Date** 2026-10-18 · **Approved by** the operator: step-31 Q-S31-2 (one currency, no barter, 2026-10-15) and the
S31-a PR design's Q-S31a-2 (2026-10-15), frozen 2026-10-18 · **Implements**
[`MODULE_SPEC.md`](../MODULE_SPEC.md) §4.1 (economy's configuration) · **Relates to** `ARC-25`, `ARC-38`,
`ARC-61`, `ARC-112`, `ARC-113`, `DEP-63` · **Design** `.structured-coding/plans/mvp0/step-31-wealth-prices.md` §4;
`.structured-coding/plans/mvp0/pr-s31a-currency-asks.md` §§5.2–5.3

**Problem.** Money already existed as integer minor units in a wallet (`ARC-38`), but nothing said what one unit
is. The 2D client divided every amount by 100, and an agent could not know the scale at all. A world whose coin
has no minor unit, or three, was shown wrongly, and the scale was a client's rule, not the world's.

**Options considered.**

```text
where the currency lives  (a) economy's world configuration,   chosen: one file per world, decoded by
                              configure/economy.yaml (ARC-61)   economy's own type, drift-checked at resume
                          (b) a section on some entity         no natural owner: a currency is nobody's
                          (c) a constant in code               a client or pack knowing a world's rule
how many                  (a) exactly one per world            chosen (Q-S31-2): a general equivalent is one
                          (b) several, with an id per amount   an id in every price, wallet and fact for a
                                                               need nobody has stated
required or defaulted     (a) required when economy is enabled chosen: no hidden default to drift from
                          (b) a default currency               a world that forgot would show a scale it
                                                               never chose
```

**Choice.**

1. `configure/economy.yaml` holds `currency: { name, symbol, exponent, symbol_at }`. `name` is 1–64 bytes of
   text without control characters; `symbol` 1–8 bytes, no control characters, no whitespace at either end;
   `exponent` 0–4 (ISO 4217's minor-unit column: JPY 0, USD 2, KWD 3, CLF 4); `symbol_at` is `before` or
   `after`. Decoding is validating: a value out of bounds, an unknown key or a missing `currency` is refused at
   its line, naming the key. All four are display data; no amount changes with them.
2. The configuration seeds one `currency-declared { name, symbol, exponent, symbol_at }`,
   `Visibility::SystemInternal`, no subjects (`ARC-61` item 8; Q-S31a-2). Its reduction starts one
   `economy-currency` Process, never woken, which holds the currency: no entity exists to carry world
   configuration at seeding (calendar's precedent, `ARC-67`). A second one is refused.
3. **Required.** Economy's reductions of `funded`, `shop-opened`, `listed` and `reference-declared` refuse with
   `economy-currency-undeclared` when no currency is declared. Configuration is seeded before sections, so a world
   that enables economy, authors an `economy:` section and has no `configure/economy.yaml` fails
   `mineworld validate`, naming the code. A world that enables economy and authors no `economy:` section has no
   amount anywhere and loads.
4. Economy discloses a `currency` record — `{ name, symbol, exponent, symbol_at, references }`, `references`
   being `ARC-113`'s reference values — about the observer itself, to every living Person observer. Every client
   and agent formats amounts from it, never from a constant. A Presentation Pack may translate `name`; it never
   changes `exponent` or an amount.
5. No currency name, symbol or exponent appears in code outside tests and fixtures (I-S31-11).

**Accepted limitations.** One currency per world and no barter (Q-S31-2); several currencies would be a clean
contract change before stabilization. Renaming a saved world's currency is configuration drift, refused at
resume (`ARC-61` item 7), as for any configuration.

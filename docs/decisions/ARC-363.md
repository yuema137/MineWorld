## ARC-363 — Places have display names, authored in the World Pack and localisable

**Date** 2026-10-27 · **Status** accepted (operator freeze of 2026-10-27, every question as recommended) ·
**Extends** `ARC-31` (names for places were "a later option") · **Notes on** `ARC-70` · **Relates to**
`ARC-26`, `ARC-82`, `D-P6-43` · **Design** `.structured-coding/plans/mvp0/pr-pdn-place-display-names.md`

**Problem.** No place had a name. The `naming` pack's `name:` section was carried by person files only, so
the 2D client showed a place as its tags joined ("cafe, public") or as "place 7", and the LM controller told
a model it worked at "cafe/public" (`D-P6-43`'s bounded fix). Tags are a world's vocabulary for rules; a name
is what people call a place, and two cafés with the same tags differ only by name.

**Choice.**

1. **Authoring.** `naming`'s `name:` section is carried by places as well as persons. It has two shapes,
   decoded by `NameSpec`:

   ```yaml
   name: Harbour Hall                 # the short form
   name:                              # the long form
     default: Harbour Hall
     forms: { zh_Hans: 港口大厅 }
   ```

   `default` (or the scalar) is a `Name` (1–64 bytes, no control character, no surrounding space). Each key
   of `forms` is a `Locale`, the stem of a gettext catalog (`en`, `zh_Hans`, `pt_BR`; pattern
   `^[a-z]{2,3}(_[A-Z][a-z]{3})?(_[A-Z]{2})?$`), so a client compares it with its settings' locale directly.
   At most 16 forms; a form equal to the default, a locale written twice and an unknown field are refused
   with the file's line and column (`DEP-10`).
2. **Facts.** A place's section seeds `place-named { place, name, forms }` (forms omitted when empty), public
   and about the place. A person's section still seeds `named`; it gains an optional `forms` omitted when
   empty, so a person named by the short form states exactly the bytes it always did. `naming` reduces both
   into `DisplayName`, whose payload gains an optional `forms`, also omitted when empty. Schema versions stay
   1: every reader reads `name` and ignores unknown fields. Places' sections are seeded before people's
   (`ARC-31` item 4), so a world that names places shifts its people's `named` event ids, and its baseline
   digests move by name.
3. **Disclosure equals the tags' audience.** A place's tags reach an observer by two routes: the place's own
   record, to whoever stands in it (`ARC-26`), and `to_tags` on a doorway, to whoever perceives the doorway's
   place (`ARC-82`). The name takes the same two routes and no other:
   - route 1: `naming` discloses `display-name` about the subject to whoever perceives it, unchanged; a person
     perceives no place but their own;
   - route 2: `door-names`, a disclosure-only record `naming` owns and never stores, about the observer's
     place: `{ leads_to: [{ to, name, forms }] }`, one entry per doorway whose destination has a
     `DisplayName`, in `Passages` order. It carries the destination's name and nothing else.
   `ways` (places reachable but not adjacent) discloses no tags and so no names.
4. **Dependency direction.** `naming` reads `movement`'s public `Passages` (a Cargo dependency, no declared
   system dependency). The optional pack depends on the fundamental one: a world with movement and without
   naming builds and runs as before, and a world without movement has no doorways and no `door-names`.
   Rejected: `to_name` in `passages` (movement would depend on naming), a name in the kernel's entity record
   (kernel ignorance), and disclosing the destination's own `display-name` (the destination is not perceived).
5. **Readers.** The protocol module adds `shown_name(id, locale)` and `door_names()`; the fallback is the form
   for the locale, else the single form for its language part (`zh` for `zh_Hans`), else the default name.
   Both Godot clients show the name before any tag wording. The LM controller learns display names, then door
   names, then tag labels, and uses the default name (no seat has a language yet). The Python SDK reads
   `door-names` (`mineworld_sdk.door_names`); the agent's `PlaceLine` carries the name.
6. **No world in code.** Names live in `worlds/*/places/*.yaml`; no code names a place or a world.

**Consequences.** A place file may carry `name:`; the generated reference lists it. Social Café and Market
Town carry the same names and `zh_Hans` forms, so `ARC-35` check 3 (Market Town's place files equal Social
Café's plus market sections) holds. Bodies Yard enables `naming` to name its two rooms.

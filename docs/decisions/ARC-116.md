## ARC-116 — The price book as perception-derived world state, and the reporter as a seat whose backend is its decision model

**Date** 2026-10-20 · **Status** accepted (step-31 approved 2026-10-15; S31-c PR design frozen by the operator 2026-10-20, Q-S31c-1 … 3 as recommended); book half implemented by S31-c, backend half by S31-d · **Approved by** the operator, directly in the primary session · **Relates to** `ARC-25`, `ARC-26`, `ARC-28`, `ARC-31`, `ARC-33`, `ARC-34`, `ARC-36`, `ARC-43`, `ARC-90`, `ARC-112`, `ARC-115` · **Design** `.structured-coding/plans/mvp0/step-31-wealth-prices.md` §9; `.structured-coding/plans/mvp0/pr-s31c-price-survey.md`

**Problem.** The operator asked (2026-10-15) for a market suggested price of essential consumables, compiled by a dedicated NPC whose backend may be a language model or a deterministic algorithm, swappable. The coordinator's restatement (step-31 §0.1, items 2–3) adds two rules: suggestions come from observed trades, and the reporter works only from what it can legitimately perceive. A stateless decision model cannot remember what it saw, and two backends driving the same seat must see the same input (F-S31-5). So the reporter needs a notebook, and that notebook must be the same thing for every backend.

**Options considered.**

| Option | Verdict |
| --- | --- |
| S28 memory as the notebook | Declined: what a memory keeps depends on the memory backend and its renderer, so a deterministic model and an LM would read different inputs |
| A public trade tape (every sale, to everybody) | Declined (step-31 §9.2): the reporter would know sales it never perceived |
| Trades reported to the reporter by sellers | Later (step-31 §9.2), as a separate pack |
| **A perception-derived book owned by a `price-survey` System Pack, disclosed to its holder only** | **Chosen** |

**Choice.**

1. **The section.** A person file's `price-survey: { kinds: { categories: [<category>] }, depth?, window?, resurvey_after? }` makes the person a surveyor. `kinds.categories` lists 1 … 16 distinct item categories (item's `Category`). `depth` is 1 … 64 notes kept per kind (default 32). `window` is `"1h"` … `"30d"`, the oldest note kept (default `"7d"`). `resurvey_after` is `"1m"` … `"1d"`, per place (default `"1h"`). A span is a whole number followed by `m`, `h` or `d`. Out-of-range values are refused at decode, naming the key. Genesis states one `survey-book-opened`, `SystemInternal`; its reduction refuses a category that no declared kind has (`survey-category-unknown`, naming the category), so a typo cannot make a surveyor that silently tracks nothing.
2. **The book.** A `PriceBook` component (component type `survey-book`) on the person holds the settings, one ring of notes per kind, and the last survey time per place. A note is `{ at, place, seller, price, source: ask | sale, in_stock }`; `in_stock` is the listing's count for a shop ask and absent for a person's ask and for every sale. A kind keeps at most `depth` notes, oldest dropped first, and kinds never evict each other. Notes older than `window` are pruned from state at each `price-noted` and filtered out at disclosure, so a note leaves the view exactly when it ages out, with no wake and no fact. Only `price-survey` writes the book, and only in its reductions of `survey-book-opened` and `price-noted`.
3. **Witnessing.** `price-survey` hears economy's `sold` through its published type. For each surveyor, it calls presence's own audience rule, `audience::admits`, with `Whereabouts::from_world` read inside the reaction. When the surveyor perceived the sale and tracks the kind, it states one `price-noted { source: sale }` caused by that `sold`, in the same revision. There is no second "same place" rule, so the book agrees with the server's frames, the perceived stream and `mineworld perceived`.
4. **Surveying.** The action `survey {}` copies what economy discloses to the surveyor where it stands: the place's shop listing, through economy's own `discloses`, and the `asks` view of every person present. It never reads `Holdings` or `Asks` directly, so it cannot learn a person seller's count. Its requirement is `at_place(<the surveyor's place>)`. It is offered **complete**, and stays safe for a controller that takes it at random (Q-S31a-3) because of a per-place cooldown: a second survey of the same place less than `resurvey_after` later is refused `surveyed-recently` (Q-S31c-2). Where no tracked ask is on display it is not offered, and a dispatch is refused `nothing-to-survey`. A person without a book is refused `NoSupportedInteraction`. `offers`, `validate` and `resolve` call one judge.
5. **Audience of the pack's facts.** `survey-book-opened` and `price-noted` are `SystemInternal` (Q-S31c-1). The surveyor already perceived each sale as `sold`; it reads its notes through its own `survey-book` record, which every backend receives in the same Observation. No inbox or memory gets a second line per sale.
6. **AC-S31-10** counts the `sold` facts **of tracked kinds** in the reporter's perceived stream (Q-S31c-3).

**Consequences.**

- Holder-only: the book is disclosed to the surveyor itself, and to nobody else. Every backend that drives the seat — the deterministic `price-reporter` model, an LM, a human, an MCP agent — reads the same record.
- Removable: a world without the pack, or with it and no section, states nothing new. The pack depends on `economy`, `item` and `presence`, so a world that enables it without economy is refused by name.
- The component type is `survey-book`, not `price-book`, because WE-a's economy Process already uses `price-book` (F-S31a-11). Prose says "price book" only for this pack's component.
- The span grammar (`m`, `h`, `d`) equals `notices`' by convention (`ARC-115`); a shared type waits for a third user.
- The pack computes no statistic and publishes nothing. Ask notes of one seller repeat across surveys, so a consumer that counts each seller once dedups by `(seller, place)` itself.

**Backend half (S31-d).** Written by S31-d as a dated note: the reporter as a seat whose backend is its decision model.

**Revisit** when sellers report trades to the reporter, when a sale form whose audience is not a place appears (the witness rule already follows presence), or when a book's size in an LM prompt becomes a problem.

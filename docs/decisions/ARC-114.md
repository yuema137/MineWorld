## ARC-114 — Wealth is a holder-only view, never stored

**Date** 2026-10-18 · **Approved by** the operator: step-31 (approved 2026-10-15), frozen with the S31-a PR design
2026-10-18 · **Implements** [`MODULE_SPEC.md`](../MODULE_SPEC.md) §4.1 · **Relates to** `INV-13`, `ARC-37`,
`ARC-38`, `ARC-112`, `ARC-113` · **Design** `.structured-coding/plans/mvp0/step-31-wealth-prices.md` §7.1–7.2

**Problem.** "Wealth matters" (operator, 2026-10-15), but a stored wealth figure would be a second account of a
wallet and of holdings, written by someone, and could drift from both.

**Choice.**

1. `wealth { amount, unvalued }`: `amount` = wallet + Σ over held kinds with a reference value (`ARC-113`) of
   count × value, in minor units with saturating arithmetic; `unvalued` = the number of held units of kinds
   without one.
2. Economy computes it when it discloses, from its `Wallet`, inventory's `Holdings` (read: economy depends on
   inventory) and `ReferenceValue`. It is a declared component type that no entity carries; nothing writes it.
3. It is disclosed to the holder only, as the wallet is (`INV-13`). Another observer learns neither wallet nor
   wealth, and economy never discloses anybody's holdings count: a Person seller's asks show only whether one
   is available.
4. No settlement path reads it, or the reference values under it.

interface (step-31 §7.4), are added by S31-f as a dated note on this record.

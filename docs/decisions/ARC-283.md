## ARC-283 — Sleep is an activity owned by a System Pack, and it ends without any other pack knowing about it

**Date** 2026-10-18 · **Status** accepted (design, step 35); to be implemented by PR N-a · **Approved by** the operator, in the primary session, 2026-10-18 (step 35 frozen; Q-S35-1, Q-S35-6, Q-S35-10, Q-S35-13, Q-S35-14 as recommended; the generic-mechanism ruling below) · **Relates to** `CLAUDE.md` §4 rules 1–3, `ARC-25`, `ARC-28`, `ARC-31`, `ARC-63`, `ARC-64`, `ARC-147`, `ARC-284`, `ARC-286` · **Design** `.structured-coding/plans/mvp0/step-35-needs-and-sleep.md` §§3, 4, 6.1, 7, 8

**Problem.** `sleep` is in `MVP.md` §5's list of interactions and has no implementation. At night the residents of Market Town keep greeting each other and wandering through the apartments (F-S35-2). Sleep must be something any controller can ask for — a rule seat, `motivated`, an LM seat, an MCP agent or a human — through the same server path. The kernel must not learn that people sleep (`CLAUDE.md` §4 rule 2). And `movement` and `conversation` must not learn it either, or every pack that a sleeper might touch would have to check for sleep.

**Options considered.**

| Option | Verdict |
| --- | --- |
| (a) Sleep inside the `needs` pack | Declined (Q-S35-1): sleep is a visible activity other people react to, while needs are a private condition. A world may want one without the other: bedtimes without hunger, or hunger without modelled sleep |
| (b) `movement` and `conversation` refuse a sleeper's requests | Declined: both packs would have to know what sleep is, and every later pack the same |
| (c) Sleep sets or requires a lying `posture` | Declined for MVP-0 (Q-S35-10): it couples two packs. Presentation shows `Asleep` over any posture; a bed anchor is a later `bodies`/`posture` refinement |
| (d) **A separate `sleep` System Pack that owns `Asleep` and ends a sleep by reacting to other packs' facts** | **Chosen** |

**Choice.** `sleep` owns one component, `Asleep { since, alarm }`, on a sleeping person, and nothing else.

- It provides `sleep { for: minutes }` (15 … 840; the alarm is now + `for`) and `wake { }`. Rules, in validation order: the actor is a living Person (else `NoSupportedInteraction`); already asleep → `Busy` for `sleep`, not asleep → `NoSupportedInteraction` for `wake`; `for` out of bound → a typed refusal naming the bound; the place is not permitted by the Interaction List → `PermissionDenied`; the sleeper is in the place (no radius).
- **Where one may sleep is data, not code.** `configure/sleep.yaml` is the pack's Interaction List section (`ARC-63`). The decision has two levels. When the world's list has a rule that matches the request, or states `default: forbid`, the list decides. Otherwise the pack's own fallback applies: sleep is allowed at places tagged `residential`, a tag in the `sleep` pack's vocabulary, so it needs no class in `configure/classes.yaml`. So an author permits a park bench or forbids sleeping in a host's home without code (N-a's PR design).
- It emits `fell-asleep { person, place }` (audience: the place's occupants). The fact carries no alarm; the alarm reaches only the holder, through the disclosure. It also emits `woke { person, slept, reason }`, `slept` in integer seconds. Neither fact is biographical by default (Q-S35-13); a world can switch that on through `consequences`.
- `Asleep` is disclosed as `{ asleep: true, since }` to everyone who perceives the person (Q-S35-14), and `alarm` to the holder only.
- One `sleep` Process per sleeper ends at the alarm. There is no periodic Process.

**How a sleep ends.** Four triggers, each one the `sleep` pack's own reaction:

| Trigger | `reason` |
| --- | --- |
| the sleeper's Process reaches the alarm | `alarm` |
| the sleeper asks `wake` | `asked` |
| `conversation`'s `spoke` whose listener is the sleeper, when the parameter `woken_by_talk` holds (default `true`) | `addressed` |
| the sleeper's own `arrived` (`presence`) or `spoke` | `acted` |

The last row keeps one truth about the body without any other pack knowing about sleep. If a controller makes a sleeper walk, the walk is real, so the person is awake: `sleep` hears the `arrived` and states `woke` with `acted`. `sleep` decodes `arrived` and `spoke` through their owners' published types (`ARC-28`); it has a registry dependency on `presence` only.

**The generic-mechanism ruling (operator, 2026-10-18).** "Do not hard-code a pile of things to make the small default world run." So nothing in `sleep` names a world, a place or a person. Where one may sleep is the Interaction List; the bounds are typed parameters (`longest_minutes` 60 … 840, default 840; `shortest_minutes` 15 … 120, default 15; `woken_by_talk`, default `true`). Every acceptance criterion of step 35 holds on Market Town and on at least one second world or a generated variant with no code change.

**Consequences.** A world that does not enable `sleep` is byte-identical to the base. `needs` hears `fell-asleep` and `woke` to switch a person's tiredness between rising and falling (`ARC-284`); `sleep` never reads `needs`, so needs have no forced consequence such as collapsing asleep (Q-S35-3). Clients render the disclosed state only: a "Zz" glyph in 2D, a sleeping pose or its fallback in 3D. The `residential` fallback is a tag the pack reads, not a world's name, so it holds in any world that tags its homes (Market Town, Social Café and Lakeside already do).

**Revisit** when a bed or a sleeping place with quality is needed (with `bodies` and `posture`), or when a world needs a forced sleep consequence, which would be a rule of another pack in the Interaction List.

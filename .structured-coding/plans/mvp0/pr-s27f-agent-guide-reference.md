## 1. Goal

A person who owns an agent (Claude Code, Codex, any MCP client, or a Python program) can follow one guide chapter,
on any of the three operating systems, from "I have the tutorial's corner shop" to "my agent walked into the shop,
said hello to Ana and bought something, and the world's own record shows it" — with a seat grant rather than the
invite, with the safety rules stated plainly, and with a real session transcript that CI keeps true. The adapter's
tool reference is published beside S25's configuration reference, generated from the same models that publish the
tool schemas, and drift-checked. The adapter serves the chapter and its own reference pages as MCP resources, so an
agent can read them from inside its session.

## 4. Reuse, both ways

Nothing is built that a tool already does: the page is executed by S25's runner (`DEP-50`), the reference is
generated from the adapter's own Pydantic models by the command that already publishes them (`ARC-90`'s drift
rule), the replay uses the official MCP client (`DEP-56`) and S27-d's real-server support. The only new code is the
Markdown renderer of the tool list (≈ 120 lines over `catalogue_json()`'s data) and the recorder/replayer of the
transcript (test code). A JSON-Schema-to-Markdown library was considered for the renderer and declined: the output
must be byte-stable across OSes and versions, the input is thirteen known tools, and a dependency would be a
second schema reader beside Pydantic for a few loops (`REUSE_POLICY.md` §12; no record needed below the
"substantial infrastructure" threshold).

### 5.2 The transcript fixture

`docs/guide/examples/agent-session.json` (2-space indented, keys sorted, LF, trailing newline):

```text
{ "world": "corner-shop", "seat": "ben", "recorded_with": "<mineworld-agent version>",
  "steps": [ { "call": { "tool": T, "arguments": A }, "error": null | <ToolError code>, "shows": { PATH: V } } … ] }
```

- **Calls.** In order: `seats`; `join {seat: ben, nickname: "agent"}`; `observe`; `walk_to {to: {place:
  "<ref:Shop>"}}`; `wait {until: {kind: walk_ended}}` (repeated by the replayer until arrived, shown once);
  `say {to: "<ref:Ana>", words: "Hello, Ana."}`; `wait {until: {kind: spoken_to}}`; `attempt {view: "<view>",
  offer: "<offer:buy>"}`; `observe {since_view: "<view>"}`; `leave`. Placeholders (`<handle>`, `<ref:NAME>`,
  `<view>`, `<offer:ACTION>`) are resolved by the replayer from the live session: a reference by the display name
  in the newest view's `here` (or `me.place`), a view by the last `view` number, an offer by the first available
  offer of that action type. The names `Shop`, `Ana` and the item are 25d's; C0 records them from the merged
  corner-shop and stops if the shop has no `buy` offer reachable by `ben` or Ana has no seat-independent reply
  (`--agent ana`).
- **Shows.** For each tool a fixed list of dotted paths (the recorder's `EXCERPT` table): `seats` → `seats`;
  `join` → `seat`, `took_over`, `view.me.place`, `view.offers[0..5].action_type`; `walk_to`, `say`, `attempt` →
  `outcome.kind`; `wait` → `woke`, `events[0].event_type`, `events[0].words.kind`; `observe` (delta) →
  `view.base_view`, `view.me.holdings`; `leave` → `closing`. Volatile values (`at`, `world_seconds_since_last_call`,
  `handle`, view numbers, reference strings, `words.text` of a resident's reply) are written `"…"`.

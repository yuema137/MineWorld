## Freeze blockers and smallest amendments

### N1 — Current host creates a new save before semantic genesis validation

Evidence tools/cli/src/serve.rs516: SqliteBackend::create occurs BEFORE pack.assemble and PersistentWorld::create. persistence/src/sqlite.rs168–180 creates directory/database/schema immediately. PersistentWorld::create in persistence/src/world.rs134 then calls world.genesis. Thus an energy model mismatch rejected only by a genesis reducer leaves an empty SQLite save; exists() checks only file existence, so a subsequent run tries resume rather than creating a valid world. NE1 promises no new save on invalid genesis and current C1 path cannot satisfy it. Listener itself is safe: serve binds only after WorldHost::spawn completes (~serve.rs306).

Required amendment: explicitly own and design generic delayed persistence creation/validation ordering before freeze, or choose a genuinely pre-backend owner validation seam. Merely moving assemble before SQLite is insufficient: assemble collects facts without reducing them. A minimal candidate to audit is a backend-factory/lazy-creation seam invoked only after in-memory genesis succeeds, before durable initialize; preserve existing create API semantics/replay and do not expose needs types to host/kernel. This touches persistence/host contracts and is currently absent from C1 scope; it must be documented/reviewed as such. Do not preflight by persisting/erasing a bad save or weakening no-save acceptance. If the team instead chooses contextual authoring, audit actual SectionInContext/ResolvesSubjects own-config seam and record that choice; no dummy owner/config manager.

### N2 — Choose the authored-error path, not just a reducer location

KernelError::FactRefusedByOwner at kernel/src/error.rs334 and dispatch.rs55–65 explicitly describes checked-constructor violation/system bug. Reduction is not transactional. Genesis records all initial emissions then reduces them (dispatch.rs510ff); an error discards the candidate world, but must not be treated as a recoverable ordinary action rejection or continue initialization. PackError wraps kernel failures as Composition (worldpack/error.rs~545). Current ordinary section seeding carries path/key into SectionRefusedByOwner, whereas reducer errors lose that loader context.

Required amendment: fix exact named code/detail and host/CLI propagation contract for cross-model/effective-capacity invalid authored content. EntityRecord::key() supplies authored subject key to owner without rereading YAML; source path/line may honestly be unavailable, as draft already says. State that failure is terminal candidate construction, no world/listener/durable save is returned. Distinguish this intended genesis validation from corruption/bugs during replay/runtime; do not weaken runtime reduction invariants. Add one actual CLI invalid-config assertion for visible owner/subject/key and no save/listener after N1 design is settled.

Draft only says executor will choose versions later.

Required amendment: version table before freeze, including configured-event/interactions schemas and disclosed needs records. Minimal reusable candidate: defaulted per-owner config-event/component version constants on InteractionSection (defaults1; needs overrides2), rather than globally bump every optional pack or keep stale shape version. Alternatively audit/document an owner-specific encoding strategy. Define exact incompatibility error precedence (configuration drift can be reported before system-version refusal) without promising all old saves produce PersistedSystemOutdated specifically. Retain matching old binary/package for existing saves; never use launcher fresh/delete to recover incompatibility.

### N4 — Feasible basket is not a guarantee for the unchanged controller

cognition/rule-controller/src/fetch.rs17–22/213ff buys the most nourishing available kind, ties lowestItemId; insufficient funds then stops. needs.rsbest_meal also ranks normalized nourishment, not cost. Therefore one cheap2000kcal basket within6slots does not establish300-day affordability when controller may repeatedly choose a dearer cafe serving, waste cap excess, or consume food to free hands. Original S35content§2.3 instead bounded even the dearest food/deficit ratio.

Required amendment: ten-row content table plus an affordability/supply proof for reachable unchanged policy choices, not merely existence of a cheap basket. Bound price/useful-energy with cap/rounding/meal timing, starting holdings/nonfood capacity, all seats/NPCclasses and daily production; include worker liquidity before first wages, organization wage outflow and discounts. If authored endowment/wages/production must change, make the concrete content revision reviewable before content freeze. No optimizer, forcedgrant or reduced rhythm threshold inferred. The existing long gates remain final empirical acceptance, not a substitute for pre-freeze sizing.

### N5 — Define byte preservation for incompatible saves honestly

serve.rs497 opens existing SQLite via PowerLoss BEFORE configuration/composition rejection. sqlite.rs216 connects read/write and sets journal_mode=WAL; close can affect WAL/checkpoint representation, especially a crash-recovery fixture. It is not established that every valid incompatibility refusal preserves the exact physical database/WAL bytes. No observed destructive mutation is claimed by this read-only audit.

Required amendment: choose whether NE5 requires logical persisted contents/no revisions appended and no re-genesis, or strictly identical files. The latter needs a read-only compatibility/drift preflight before writer open plus crash-tail/WAL evidence, and belongs in the explicit persistence scope. Do not claim byte-for-byte nondestructiveness solely from a version error. User saves remain read-only during development in either case.

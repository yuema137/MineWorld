# Playable contextual dialogue and persistent memory — integration design audit

Date: 2026-11-23. Status: READ-ONLY SOURCE AUDIT; proposed implementation route, not DESIGN FROZEN or runtime acceptance. Owner: delegated integration audit. No child agents. No inference, downloads, cargo, Godot, secret reads, paid endpoints or public services used. Only this report was written. Repository production/planning files remain untouched by this audit.

## 1. Decision in brief

Reuse the existing `mineworld-cognition` Python protocol client, model gateway, controller and SQLite memory home. Start with ONE explicitly selected resident on the already installed local `qwen3.5:4b`; all remaining seats continue under `server --town`. There is no justification for another brain framework, database, model SDK or public dependency. Local model availability is the coordinator's read-only `ollama list` evidence, not proof of useful inference or sufficient shared-machine performance.

The delivered launcher does not start cognition at all. Existing memory infrastructure is substantial, including restart fixtures, but neither a SQLite file nor the existing earliest-line quotation test establishes the newly requested contextual conversation. The smallest delivery is a bounded lifecycle/configuration integration plus deadline correction and behavior acceptance; it is not an LLM for every resident.

## 3. Current execution paths

- `tools/launch/src/children.rs::Server::start` passes `--agent alice --stop-on-stdin-eof`, not `--town` or `--decisions`. `tools/launch/src/lib.rs` starts server, obtains join information, runs one/two clients, then stops server. No cognition process exists in that ownership graph. The separately owned town/admin launcher correction must be integrated first or coordinated through a clean successor base.
- Source `mineworld-slice` and `mineworld-2d` already support played town hosting, per-world saves and owned-server cleanup. Neither contains cognition/decisions wiring. The existing keep-town-running branch in source scripts must not silently become the packaged lifecycle policy; the operator requires retaining packaged both-client shutdown semantics.
- `cognition/lm-controller/examples/alice-lm.decisions.yaml` declares external `lm` with `fallback: rule`, assigning Alice only. `mineworld decisions <world> --decisions <same-file> --json` emits format 3; `controller/assignment.py::read_assignment` selects `model.assigned == "lm"` and optionally narrows seats. The exact same decision file must be passed to the server and resolution command on every start.
- `python -m mineworld_cognition --config FILE` reads that JSON, invite from a named environment variable, operator-owned endpoint/config/store, constructs one shared Router and SeatHomes, then one SeatRunner per selected LM seat. Each joins through SDK protocol. It does not possess a world handle or mutate world components.
- `SeatRunner` joins with `take_over=False`: it may occupy a hosted fallback seat, but does not forcibly steal a human seat. Lost/occupied seats are retried. Consults use perceived events, latest Observation, persona and recalled memory, validate output and rebuild against current offers, then submit via SDK. Movement pacing already exists despite the old MODULE_SPEC sentence saying the LM controller never chooses movement; reconcile that stale sentence against existing LE-c additions rather than preserving an inaccurate description.
- Speech detection is specifically a `spoke` addressed to the seat. Generic ambient chat is not a guaranteed direct reply trigger. The pending policy permits one in-flight consult and one replaceable waiting trigger: rapid speech can deliberately supersede/drop previous lines. Acceptance must use serial turns and separately verify this overload behavior.

## 4. Memory ownership, persistence and takeover

`controller/homes.py::SeatHomes` is the only controller opener/closer. Default `[memory] sharing = "home"` uses `<store>/<world-instance>/memory.sqlite`; `none` uses `<store>/<world-instance>/<seat>.sqlite`. The process owns an exclusive SQLite home lock; multiple cognition processes must not share a writable home. One process can hold several seats without sharing their knowledge. Shared fact storage does not grant another seat access.

`MemoryHome` schema is currently 6. Seat identity includes world instance, seat key and self EntityId; mismatch and unsupported schemas are named errors. `memory/ingest.py` inserts perceived events, derived episodes/chapters/stable facts/names and cursor in one transaction; identical redelivery is a no-op. SeatRunner absorbs before trigger detection. Its durable cursor suppresses retriggering already absorbed historical lines after a process restart. History received while cognition was absent can be rebuilt from that Person's perceived stream, including encounters while a human or rule controller held the same identity. This is not transfer of human thoughts or arbitrary model internal state.

The home is OUTSIDE `save/world.sqlite` by architecture. Merely copying a world save does not copy controller memory; a retained world history can support rebuilding under the selected memory policy, but exact preservation of old private summaries/forgetting cannot be promised by copying only world state. Use a stable per-save-slot operator cognition directory outside the save, retained across package upgrades. Resume files/logs are `<store>/<seat>.resume` and `<store>/<seat>.decisions.jsonl`, so use a different top-level store per selected save slot, even though home files contain world-instance subdirectories. Budget ledger is separate from memory and should be durable too. Never prune cognition as one of five launcher run logs.

`--fresh` creates a new world instance and therefore a new home; old memories must not cross to it. Define cleanup explicitly, without deleting another slot's history. Restoring an older backup with the same instance alongside a newer memory home is a separate rollback hazard: a cursor ahead of restored history must not inject knowledge from the discarded future. For the minimal release, do not advertise arbitrary backup rollback; restored backups require a matching stopped cognition snapshot or a fresh derivation directory. Record/test this limitation rather than claiming an atomic world+cognition backup already exists.

A human taking a seat preserves authoritative Person identity, inventory, relationships and biography. The cognition client must stop submitting as that seat, respect the normal seat-loss/rejoin protocol, and rebuild only what the Person was permitted to perceive during absence. Test re-entry explicitly; memory possession is controller-side, not a new kernel Person field.

## 5. Concrete gaps and robustness findings

1. **No delivery wiring:** launcher lacks external-controller assignment, cognition runtime, operator configuration, stable store, child supervision and a visible readiness/degraded state.
2. **Python package omitted:** `scripts/package.py::layout` copies server, worlds, presentation and shared settings; it does not package Python, SDK, cognition or their dependencies. A source virtualenv does not prove an exported app can run cognition on a clean machine. Python requires >=3.12 and installed distribution metadata for retry/breaker/retention/scope entry points. Copying source files alone is insufficient.
3. **Deadline is not end-to-end:** `gateway.py::complete` waits on `budget.limiter` BEFORE `asyncio.timeout(limit)`. `consult.py` has no outer timeout around `deps.ask`/submit and does not recheck remaining time immediately before a successful submit. `seat.py::_consults` drops stale pending triggers but starts a new full deadline inside consult; time already spent pending/awaiting first Observation is not subtracted. A waiter may exceed the advertised trigger-to-submit budget. Correct with one absolute deadline propagated through queue admission, HTTP, retry delays and submission, release reservations/limiter on cancellation, refuse late proposals. Test under two seats/one blocked slot, not only one stalled HTTP request.
4. **Fallback is available but not a guaranteed answer:** on failure/budget/breaker, `SeatRunner` leaves only if `welcome.took_over == "hosted"`; otherwise it stands. Hence `--town` and matching assignment are essential. Hosted handback resumes rule behavior; it does not necessarily answer the original timed-out utterance, since paced rule reply considers only its current consult window (`paced.rs::answer`). Do not report a contextual reply on timeout or fake remembered speech. Other residents must demonstrably keep acting while the model stalls.
5. **Defaults are not an affordable acceptance gate:** `examples/local.toml` permits five calls/consult and multiple retry layers, while local budgets default to 20 calls/hour per seat, 30000 tokens/day and two in flight. The sample also has stale format-1 and FG-c-not-merged comments. Generate a reviewed operator config instead of shipping these settings blindly.
6. **Citations are necessary, not sufficient:** `validate.py` refuses forged recall tokens and invalid targets/offers; it does not prove the semantic truth of a model's prose. A model can cite a real memory and still misstate it. Inspect both model input/citations and actual saved utterance. Existing rule `act.rs::reply_to` literally says “I remember you” while quoting current/recent disclosed speech; that wording is not durable contextual recall acceptance.
7. **Bounded concurrency is not a global rate cap:** gateway budgets are per-seat windows with a process-wide semaphore; semaphore waiters are not an explicit fixed-size global queue. Initially one LM seat bounds pending work. Scaling to many seats needs a separately specified admission/global-world budget, not a claim that `max_in_flight=1` limits total daily work. Runner `_records` also retains all decision records in process memory; review this existing growth before scale claims.

C. **One supervised local cognition child.** Extend existing launcher lifecycle with optional typed local cognition configuration, matching resolved format-3 decisions, and one selected resident. D. **Single shutdown owner.** Retain the launcher as supervisor of server, cognition and client(s). Closing the final reference client or a failed launch first signals owned cognition, lets its existing Stopper cancel work and leave seats (5s leave, 15s forced bound), then closes server stdin and awaits normal durable shutdown under its existing bound. Stop only tracked owned PIDs; do not kill an already running user's Ollama service or use process-name searches. Handle launcher error/drop paths and two-window lifetime. Abrupt supervisor death needs explicit orphan cleanup evidence. HTTP cancellation is not proof that Ollama stopped GPU work; observe this in the eventual local gate. If supervisor starts a model service, that is a separate owned-child lifecycle amendment, not a hidden action.

E. **Source then export.** First validate server + Python cognition through the real protocol using installed locked dependencies. For this Mac's source run, existing Python workspace and existing model service may be prerequisites. For a self-contained exported conversation delivery, select and prototype a target-specific Python/cognition runtime artifact using existing locked packages, record licences/size and preserve entry-point metadata; do not install/download on app launch. Alternative user-installed Python/cognition is a declared prerequisite and is not a clean-machine self-contained package. No particular bundler/new dependency is selected or authorized by this audit. Update `scripts/package.py`, bundle contract and smoke/real play evidence accordingly. Source success alone must not close the exported integration row.

Record total calls/tokens including incidental arrival/need/upcoming triggers and failures. Eight calls must be an observed harness/global gate cap, not merely a claim inferred from per-seat production budgets. Serial speech and explicit trigger counts avoid ambient activity silently consuming the cap. Stop on bound; report INCONCLUSIVE/FAIL, never silently raise it.

Before/after compare rule-only world and same world with one LM seat: server tick/action responsiveness, other NPC travel/actions, first usable frame, dialogue latency, CPU and unified-memory pressure. Model file size alone gives no RAM/GPU headroom claim. Stop model admission on failure without stopping the world. A local-only gate has no monetary cost but does consume this shared Mac; schedule within coordinator capacity, no concurrent heavy run.

## 8. Exact behavioral acceptance and evidence

Use short nonce facts created AFTER the run starts; do not put expected answers in persona or the final question. Preserve Event IDs and exact source/configuration. Example serial dialogue with resident A and player P:

1. P tells A: “My parcel code is MAPLE-47; pickup is the bakery.” A gives a relevant acknowledgement/question, not a generic quote. Save the accepted player and NPC `spoke` facts and consult log.
2. Leave/rejoin. P asks “Where is my pickup, and what code did I give you?” A answers bakery and MAPLE-47 from cited earlier perceived facts. The question itself contains neither answer.
3. P changes the plan: “Correction: pickup is the library; the code stays the same.” Add one unrelated short exchange, and let a different rule resident perform a recorded movement/action. This creates intervening facts and a newer relevant correction.
4. Gracefully save/close ALL owned processes. Reopen the exact same save and stable cognition slot, reconnect P to the same EntityId. Ask “What is the current pickup location and code?” Require **library and MAPLE-47**, with correction and initial-code Event IDs in the model's shown memory/valid recall references. An answer only repeating the first bakery line fails. The saved NPC utterance must be caused by this consult's accepted ActionIntent. No expected answer injected into trigger/prompt/test persona.
5. While A is absent and cannot perceive, another person privately states a different nonce/location. On query A must not know it or have its Event ID/content in recall. A second resident sharing the same home must not acquire P's private exchange merely through shared SQLite. Assert actual disclosure conditions, not merely geographical absence.
6. Take A through rule -> human -> cognition release/rejoin. Assert stable A EntityId, wallet/inventory/relationship/history; no concurrent stale submit or human seat theft. Create a short encounter during cognition absence that A legitimately perceives, then verify it can be recalled after re-entry. Internal human thoughts are outside acceptance.
7. Stop/unreachable/malformed/slow model and exhaust the gate budget deliberately with scripted faults first. Assert bounded fallback, released slot/reservations, other NPC actions during the stall, normal saving, model unplugged world and no cloud attempt. Repeat shutdown during an in-flight request and with two clients; first client exit must preserve second-client play, last exit leaves no owned children.
8. New/fresh world does not recall the prior world's nonce. Restart with retained home does not repeat answers to old triggers. A missing home may rebuild from permitted history; label this rebuild separately from persistence reuse. Memory home created marker/cursor and retained records are supporting evidence, never the whole acceptance.

Extend/reuse `tools/cli/tests/milestone_d.rs`, `speech_both_ways.rs`, `cognition/lm-controller/tests/test_controller_seat.py`, `test_controller_consult.py`, `test_controller_homes.py`, `test_home_isolation.py`, `test_milestone_d_replay.py`; avoid a parallel harness duplicating their protocol lifecycle. Existing Milestone D covers process kill/restart, world/person identity, earlier context/citation and persisted action linkage, but defaults to scripted earliest-line quotation and protocol clients tagged 2d/3d. It is not proof of actual exported Godot windows or live semantic correction recall. Its 100-day memory fixture is useful later; do not run that heavy scenario as the first player-loop gate.
